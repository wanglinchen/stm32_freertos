# 上板验证（无 QEMU 时的 HIL 勾选项）

CI 不连板时，下列项须在 **userdebug** 镜像上人工勾选一次；结果记入发版备注。

| # | 项 | 操作 | 通过标准 |
|---|-----|------|----------|
| 1 | 上电短鸣 | 复位后听蜂鸣 | 约 80 ms 一声（`app_sample` 自检） |
| 2 | 四键蜂鸣 | 各键按住 ≥0.1 s | 按住响、松开停；KEY2(PC13) 与其它键一致 |
| 3 | 调试串口 | USART1 115200 | 上电见 `stm32-freertos: USART1 115200 debug ready` |
| 4 | IWDG | 故意 panic 后等约 4 s | 板子复位（非永久死机） |
| 5 | `.noinit` 现场 | GDB 读 `g_panic_record` 后软复位再 panic | 代际/序号行为与 `架构缺陷.md` 描述一致 |
| 6 | 屏三色块 + 文字 | 复位后目视 | 上红 / 中绿 / 下蓝；蓝区黑条上有 ASCII 两行与「中文显示」四字，字形清晰不断笔 |
| 7 | 桌面 | 复位后目视 | 满屏深灰窗口，标题 `P5 desktop - tap twice to enter`，横排 8 个大图标 `LED` / `KEY` / `BEEP` / `CALC` / `SETTINGS` / `PIC` / `NOTE` / `CAL`（4 列 2 行，第 1 行 120 px 起、第 2 行 256 px 起） |
| 8 | 图标命中 | 手指点任一图标 | 按下时该图标变黄，串口打 `[menu] touch down x=.. y=..`，抬手打 `[menu] tap id=<1..8> act=1`，id 与手指所在图标一致（同时决定坐标有没有左右反） |
| 9 | 双击进入 | 350 ms 内点同一图标两次 | 屏切到该应用；串口 `[menu] tap id=<id> act=2` + `[menu] enter <name>` |
| 10 | BACK 返回 | 应用内点左上 `BACK` | 回到桌面；串口 `[menu] tap id=255 act=3` |
| 11 | 连点 | 同一图标连点 10 次 | 10 行 `[menu] tap`，id 不变、无丢失；`[post] ui` 的 `ovf` 仍为 0 |
| 12 | LED 应用 | 进 `LED`，点 RED / GREEN / BLUE | 对应灯亮，屏上按钮同步变亮；点 `BACK` 三灯全灭 |
| 13 | KEY 应用 | 进 `KEY`，按住任一键 | 屏上对应方块反色，松开恢复（100 ms 刷新） |
| 14 | BEEP 应用（**已禁用发声**） | 进 `BEEP`，点 `BEEP` 按钮 | **应当一声都不响**（2026-11-25 用户要求蜂鸣器永久禁用，见 `.skills/SKILL.md`「硬规则」）。串口出现 `[app_beep] req on (muted)` 说明请求到了执行器、被策略吞掉；开机首次请求还会有 `[beep] on request ignored: buzzer disabled by policy`。窗口标题是 `BEEP - disabled`。**若真响了就是策略被绕过，按缺陷处理** |
| 15 | 计算器 | 进 `CALC`，按 `1` `+` `2` `=` | 显示区依次显示 `1` / `1` / `2` / `3`；串口每键一行 `[app_calc] key <label> disp=<值>`。按 `C` 归零，按 `/` 后再按 `0` `=` 显示 `Err` |
| 16 | 计算器边界 | 连按 7 位以上数字 | 显示停在 `9999999`（`CALC_VAL_MAX`），不溢出成负数 |
| 17 | 设置页背光 | 进 `SETTINGS`，点 `BL` | 背光立即灭 / 亮（真调 PB5，不是只改屏上文字）；串口 `[app_settings] bl=<0/1> dbl=<档>` |
| 18 | 设置页双击间隔 | 点 `DBL` 循环三档 | 状态行档位 250 → 350 → 500 循环；**改到 250 后快速点图标两下应更容易被判成双击**（光看数字变化不算验过） |
| 19 | 设置页不持久 | 在 `SETTINGS` 改完两项后复位 | 背光回默认亮、双击间隔回 350 —— 本批只回写 RAM，24C02 在 P6 |
| 20 | 图片查看器 | 进 `PIC` | 屏上出现卷里那张 BMP（240×320 竖构图，1:1 居中、不缩放）；串口 `[post] menu` 行有 `pic=240x320b24`，点 `BACK` 回桌面 |
| 21 | 记事本输入 | 进 `NOTE`，依次点 `9` `4` `6` `6` `4` | 拼音行显示 `94664` + 首个匹配音节 `xiong` 后跟 `+`（这串数字同时匹配 `xiong` 与 `zhong`，候选条 18 个字排在 4 页里） |
| 22 | 记事本多音节候选 | 接着点 `>` 翻到第 2 页，点第 3 格 | 文本区出现「中」；`[post] menu` 行 `note=2:d6d0/2:18` 与之对应（POST 走的就是这条路径） |
| 23 | 记事本退格 | 拼音状态下点 `DEL` | 先删掉一位数字（`9466`），拼音全删空后再点才删文本最后一个字（汉字按 2 字节整字退） |
| 24 | 记事本不持久 | 输入几个字后点 `BACK` 再进 `NOTE` | 文本仍在（模块 static，不随退出清空）；**复位后清空** —— 只存 RAM，`disk_write` 未实测，不写盘 |
| 25 | 日历 | 进 `CAL`，目视 | 当月月历 7×6 网格，今天（编译日期 + 开机秒）绿底；标题下显示年月与时分秒走时；点 `<` / `>` 切月立即重画 |
| 26 | 日历与 RTC 的关系 | 断电 10 s 后上电，进 `CAL` | 日历时间仍是**编译时刻 + 本次开机秒数**（`app_calendar` 还没切到 RTC 墙钟）；但 `[post] rtc` 行已经能读到真 RTC 的时间，两者当前是两条独立的时间源 |
| 27 | 满额图标 | 目视桌面 | 8 个图标正好打满 `APP_COUNT_MAX`；再加应用必须先扩这个上限，否则第 9 项会被注册表静默丢掉 |
| 28 | 自检 RTC 走时 | 开机看串口 `[post] rtc` | `src=lse`（LSE 一次起振，没降级 LSI）、日期 = 固件编译日、`walk=1s`；**连续复位 3 次**，三次时间应递增约等于复位间隔（说明已初始化的 RTC 不被重设，日历跨复位继续走） |
| 29 | 自检 ADC 温度 | `[post] adc` 行 | `cal` 两点自洽（cal110 > cal30）、`t=` 在 20~60 °C 量级；用手捂住芯片十几秒再复位，`raw` 应上升几个码（变化量不保证，只作趋势参考） |

| 31 | 自检 RNG | `[post] rng` 行 | `n=16 distinct=16 degen=0`；复位后再看允许 `distinct=15`（一次碰撞的容差），但 `degen` 必须恒为 0 |
| 32 | 串口命令行 `fml_shell` | 打开串口终端（115200 8N1），**逐字敲**（别整行粘贴，见下）`help` / `uptime` / `rtc` / `temp` / `led 0 1` / `led 0 0` / `i2c scan`；再敲 `led 3 1` / `i2c rd 7f 00`（地址越界）/ `badcmd` | 每条先回显 `[shell] > <行>`，再打结果：`cmds=8:help, uptime, rtc, temp, led <0..2> <0|1>, i2c scan | i2c rd <a7> <r8>, tone <hz 20..20000> <ms 1..5000>, vol <0..63>`、`uptime=<n>ms`（两次敲应递增）、`rtc=<日期> <时分秒> src=lse`、`temp=<x.x>C raw=<n>`、`led 0=1` / `led 0=0`（RED 真亮灭）、`i2c scan: <应答地址表> n=<个数>`；三条错误分支分别打 `usage: led <0..2> <0|1>` / `usage: i2c rd <a7 08..77> <r8 00..ff>` / `unknown 'badcmd', type help`。开机应见 `[shell] ready cmds=8, type help`。**`beep` 命令已删除**（蜂鸣器永久禁用，见第 14 项）。**限制**：接收是 10 ms 轮询 + F4 无 RX FIFO，整行粘贴会因 ORE 丢字节（表现为只进第一两个字符、无回显），这不是坏了 |
| 33 | 音频 `codec` 自检 | 上电看 `[post] codec` 行 | `codec 1a regs=14 ack=14 PASS`。WM8978 是**只写** I2C 器件（P6c-0 实测：地址 ACK、读方向 NACK），所以它没有"读回对不对"这条判据，能拿到的硬证据只有"14 条写事务是否全部 ACK"。`ack < regs` 就说明地址/时序/总线里有一处不对，不是"声音小一点" |
| 34 | 音频 `sai` 自检（**要听**） | 上电看 `[post] sai` 行，同时**听板上的喇叭/耳机** | `sai fs=47973 frames=2048 us=42656 expect=42690 err=0 PASS`：判据是"数据流段实测时长与 frames/fs 相差 ≤ 5%+200 µs 且 err=0"。**串口这一行只证数据按时钟流走了，"真的出声"必须人耳**：POST 期间会播 2048 帧 1 kHz 方波（≈43 ms，听感是一声短促的"嘀"）。一声都不响就按缺陷处理（先查 codec 的 DAC/输出路径寄存器，再查喇叭接插件） |
| 35 | 音频 `tone` / `vol`（手敲） | 串口逐字敲 `tone 1000 300`，再敲 `vol 20`、`tone 440 500` | `tone 1000Hz 300ms ... ok`（该行在声音结束时才出现，因为播放是阻塞的）；`vol 40` → `vol=40`。**蜂鸣器与本项无关**：出声的是 WM8978 + 喇叭/耳机，蜂鸣器那条路径仍被 `BEEP_ALLOW_ON=0` 断路（第 14 项） |


> 第 2 项原为「运行灯 1 s 红绿互斥闪烁」：P5a 已删掉 1 s 心跳（它会与 `app_led` 抢同一组灯，
> 屏上显示的状态与灯的实际状态在 1 s 内对不上），灯改由应用独占。逐灯行为见第 12 项。

刷机：`python flash/flash.py`（默认 `out/userdebug/objects/target/*.elf`）。
