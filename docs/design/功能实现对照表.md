# 参考工程功能对照与实现路线

分支 `feature/full-demo`，基线 `a9984a7`（`main` 上只有 7 个设备：debug_uart / leds / i2c_gpio / keys / pcf8574 / beep）。**本文是目标态清单，不是现状描述**；每一批完成后回填「状态」列。

## 0. 三条硬约束（先于任何取舍）

| # | 约束 | 出处 | 对实现的含义 |
|---|---|---|---|
| 1 | 层边固定：`bsl → hal`、`fml → bsl / osl`、`apl → fml / bsl / osl` | `project/generate.py` 的 `LAYER_DEPENDENCIES` + `docs/design/系统设计.md` §五层栈 | `bsl` 里不许 include `fml_*`；`fml` 里不许 include `stm32f4xx_hal.h`；应用不写寄存器 |
| 2 | 设备事实只有一份：`docs/hardware/pinmap/*.xlsx` → dtsi → `out/dts/apollo.dts` → dtc → `.dtb` 段 | `project/generate.py::_BOARD_NODES`、`docs/hardware/pinmap/README.md` | 引脚/极性/地址/时序参数写进 DTS，C 里不留第二份常量；驱动只调 `board_rt_*` 取值 |
| 3 | 声明必须有符号：头里声明的函数，镜像里必须 `nm` 得到 | `bsl/inc/bsl_device.h` 注释（第八轮删 `bsl_device_get`） | 不为「看起来能走」的面子接口写声明；解析出来的事实必须有人消费 |

另外两条现行口径（2026-11-22 起）：门禁 `verify` / `gate-selftest` 已整体删除，验收靠 `update` 零 dtc 诊断 + `build` 零告警 + 上板串口证据；`bsl_init_level_t` 只有 `POST_CLOCK` / `BOARD` 两级，**不为新外设新增级别**。

## 2. 新增一个设备的六步（照抄即可，每步都有落点）

以 `board_lcd` 为例，其余设备同构：

| 步 | 落点 | 内容 | 易错点 |
|---|---|---|---|
| 1 | `docs/hardware/pinmap/apollo_alternate_gpio_pinmap.xlsx` | 引脚归属（LTDC 的 RGB/HS/VS/DE/CLK、背光脚） | 表里已有网络名，别在 C 里再抄一份 |
| 2 | `project/generate.py::_BOARD_NODES` | 加 `panel: panel { compatible = "brd,ltdc-panel"; ... }`，含时序参数（hsw/hbp/hfp/vsw/vbp/vfp、像素时钟） | 模板只有一份，`refcheck.py` 会复算 `out/dts/apollo.dts` |
| 3 | `bsl/inc/board_rt.h` + `bsl/src/board_rt.c` | `board_rt_panel_*()` getter（宽/高/时序/背光脚） | getter 只读 DTB，不缓存第二份真源 |
| 4 | `bsl/inc/board_lcd.h` + `bsl/src/board_lcd.c` | `bsl_err_t board_lcd_init(void)`；操作函数 `board_lcd_fill/rect/pixel`；`const bsl_lcd_api_t bsl_api_brd_ltdc_panel`；`const bsl_device_driver_t bsl_driver_brd_ltdc_panel` | `init` 必须返回 `bsl_err_t`，失败留状态位（`bsl_device_mark` 由 `bsl_init_run` 写） |
| 5 | `bsl/inc/bsl_device_api.h` | 加 ops 结构 `bsl_lcd_api_t`（只有运行期操作，**不放 init**） | init 只有 `bsl_device_driver_t.init` 一个入口 |
| 6 | `bsl/inc/board_device_registry.h` | `bsl_dev_id_t` 加 `BSL_DEV_LCD`；`BOARD_DEVICE_REGISTRY_APPLY` 加 `M(BSL_DEV_LCD, "panel", BSL_INIT_LEVEL_BOARD, bsl_driver_brd_ltdc_panel, 0)`；加 `bsl_devapi_lcd()`；同步 `BSL_DEV_COUNT`（`bsl_device.c` 有 `_Static_assert` 守着） | 第 2 参数就是 DTB 节点名，两者必须一致 |

`optional` 语义（第 5 个宏参数）：`0` = 必需（缺失即 `bsl_board_periph_init()` 返回错误）；`1` = 可降级（消费方自己判 `bsl_device_is_ready()`）。屏、SDRAM、NOR 是 `0`；传感器类可 `1`。

**不新增 init 级别**：显示链与触摸都在 `BOARD` 级，靠 `BOARD_DEVICE_REGISTRY_APPLY` 里的行序保证先后（SDRAM 在前、LCD 在中、TOUCH 在后）。如果将来确实需要「时钟后、板级前」的第三级，必须同时改 `bsl_init.h` 与 `docs/design/系统设计.md`，属架构变更，单独一批做。

## 3. fml 与 apl 的规约

| 层 | 命名 | 入口 | 约束 |
|---|---|---|---|
| `fml` | `fml_<domain>.h/.c` | 无全局 init，按需被 apl 调用 | 只 include `bsl_*` / `osl_*`；不碰 HAL；不保存设备实例指针以外的板级事实 |
| `apl` | `app_<name>.h/.c` | `void app_<name>_start(void)` | 任务用 `osl_thread_create(fn, name, OSL_THREAD_STACK_WORDS_DEFAULT, arg, prio)`；失败 `fml_panic(2U)` |
| `apl` | `app.c` + `app.h` | 应用注册表：`app_id_t` / `app_desc_t{id,name,start}` / `APP_TABLE` | 新增应用只改这张表 + 一个 `app_<name>.c`，`main.c` 不动 |

**新任务必须登记 health 槽位**：`osl/inc/osl_health.h` 的 `OSL_HEALTH_SLOT_*` 与 `OSL_HEALTH_STACK_SLOTS` 同改，任务体内每个循环调一次 `osl_health_stack_mark(slot)`。历史上踩过「池满静默 return」「槽数少一个导致最低水位永远是 0」两个坑，别重犯。

**RAM 预算**：每任务 256 words（1 KB）静态栈；`app_menu` 这类常驻任务单独给 512 words。当前 `bss` 已到 93 KB 量级，显示链（帧缓冲）必须放 SDRAM，不能进 `.bss`。

**日志**：一行动作用一次 `BSL_LOG_MOD_INF("mod", "...")` 打完整行（`bsl_log_mod_puts` 分多次会重复前缀，历史踩过）。应用心跳格式沿用 `[calc] poll=.. ev=.. ms=.. err=..`。

| **P6** | 音频/传感器/通信/扩展 | `board_es8388` `bsl_sai` `fml_audio` `board_imu` `board_ap3216c` `board_eeprom` `board_tpad` `bsl_rtc` `bsl_adc` `bsl_can` `bsl_uart` `fml_shell` `fml_qr` `fml_nes` | `sai` `rtc` `adc` `can` `usart2` `usart3` | `codec` `sai` `rtc` `als` `imu` `eeprom` `tpad` `adc` `can` `rng` | 每项一行 PASS |

依赖链：P0a → P0b → P1 → P2 → P3 → P4 → P5；P6 可插在 P2 之后并行（音频不依赖 UI，传感器不依赖字库）。

### P0a 落地记录（2026-11-24）

| 项 | 值 | 出处 |
|---|---|---|
| 容量 / 基址 | 32 MB @ `0xC0000000` | DTB `sdram@c0000000` 的 `reg` |
| SDCR | `0x19D9`（9 列 / 13 行 / 16 位 / 4 bank / CAS 3 / HCLK÷2 / 突发） | 参考工程 `sdram.c` 的 `sdctrlreg` |
| SDTR | `0x01115561`（TMRD 2 / TXSR 7 / TRAS 6 / TRC 6 / TWR 2 / TRP 2 / TRCD 2） | 参考工程 `sdram.c` 的 `sdtimereg` |
| 刷新计数 | **636**（64 ms × 84 MHz ÷ 8192 − 20） | 本工程 HCLK = 168 MHz 重算；参考工程是 192 MHz → 730，**不可直接抄** |
| 引脚 | 5 组「端口 + 掩码 + AF12」 | `0x000d`(C) `0xc703`(D) `0xff83`(E) `0xf83f`(F) `0x8137`(G) |
| 自检 | 4 KB 步长、8192 点写读 | `board_sdram_selftest()`，实测 `bad=0` |

副产物 `bsl_gpio_init_af()`：复用功能输出（af 0..15，端口认不出或越界返回 0），P0b 的 LTDC 引脚直接复用。

两个踩过的读数陷阱已写进 `串口自检_1项_2026-11-24.txt`：`VTOR=0x1FFF0000` 不代表固件没跑（SRST 会把 CPU 拉到系统存储器）；pyserial 抓包 0 字节不代表板子静默（同刻直读能拿到日志）。

### P0b 落地记录（2026-11-24）

| 项 | 值 | 出处 |
|---|---|---|
| 面板 | 4.3 寸 800×480，ID `0x4384` | 参考工程 `ltdc.c` 的 `0X4384` 分支 |
| 时序 | hsw 48 / hbp 88 / hfp 40；vsw 3 / vbp 32 / vfp 13 | 同上 |
| 像素时钟 | 33 MHz：VCO 396 MHz(N=396) → R=3 → 132 MHz → DIVR=/4 | PLLSAI 输入 = HSE/PLLM = 1 MHz，**与主 PLL 的 N 无关**，所以 168 MHz 下同样成立 |
| PLLSAI 寄存器 | `PLLSAICFGR=(396<<6)|(3<<28)`、`DCKCFGR[17:16]=1` | 参考工程 `ltdc_clk_set` |
| 极性 | `GCR=0`：像素时钟不反向、DE/VS/HS 低有效 | 参考工程非 10.1 寸分支 |
| 层 1 | `PFCR=2` `CACR=255` `DCCR=0` `BFCR=(6<<8)|7` `CFBLR=(1600<<16)|1603` `CFBLNR=480` | 参考工程 `ltdc_layer_parameter_config/_window_config` |
| 引脚 | PF10=DE；PI9=VS、PI10=HS、PI0..2+PI4..7=数据；PG7=CLK、PG6+PG11=数据；PH9..15=数据，全 AF14 | 参考工程 `ltdc_init` |
| 背光 | PB5，高电平点亮 | 参考工程 `ltdc.h` 的 `LTDC_BL_GPIO_*` + `LTDC_BL(1)` |
| 帧缓冲 | `0xC0000000`，取 sdram 节点 `reg[0]` | DTB `framebuffer = <&sdram>` |

自检口径：`board_lcd_selftest()` 返回 7 项读回的不一致数 —— `SSCR/BPCR/AWCR/TWCR`（按 DTB 重算期望）+ 层 1 的 `CFBAR/CFBLNR/PFCR`。实测 `bad=0`。

同一事实只写一处：宽高、时序、PLLSAI 参数、引脚、背光极性全在 DTB `panel` 节点；`board_rt_panel()` 一次解析成套返回（用结构体而不是十三个标量 getter，缺一项就整体失败）。`lcd_exp_*` 公式在 init 与 selftest 之间共用，避免"改一处、另一处按旧值判定通过"。

`bsl_fb`（点/线/矩形原语）**不在 P0b**：它没有消费者就没有验收标准。挪到 P1，与 `fml_gui` 字库一起交付 —— 届时屏上要能显示一段文字，才是它的判据。

## 5. 成色分级（每个模块必须到 L2 才算完成）

| 级 | 定义 | 判据 | 是否计入「完成」 |
|---|---|---|---|
| L1 探针 | 直接写寄存器做一次读回 | POST 一行 PASS | 否（只能证明器件在动） |
| L2 驱动 | `board_<dev>.c` + `bsl_err_t init` + 操作函数 + `bsl_api_*` + registry 行 + DTB 取事实 | `nm` 有符号、`bsl_device_is_ready()` 可判、失败可读 | **是** |
| L3 可用 | `fml` / `apl` 真实消费（有界面或数据流） | 上板可见现象 + 串口心跳 | 应用类才要求 |

历史教训：之前 30 多项 PASS 里，ADC/RTC/CAN/SAI 等多数停在 L1（`bsl_probe` 直读），应用无法调用。本分支一律按 L2 交付，L1 只作为 L2 的前置调试手段。
