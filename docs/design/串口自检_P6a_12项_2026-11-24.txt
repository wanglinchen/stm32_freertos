==========================================================
二、判据拆解（每一项「过」到底证明了什么）
==========================================================

1) rtc src=lse 2026-11-24 16:41:01 walk=1s
   - `src=lse`：LSE 起振（RCC_BDCR.LSERDY 在 3 s 内起来），**没有降级到 LSI**。
     走时源是板上 32.768 kHz 晶振，不是片内 RC。
   - 日期 2026-11-24 = 固件**编译日**（bsl_rtc.c 的 __DATE__）。本机没有墙钟来源，
     首次初始化只能种编译时刻，这是唯一诚实的起点，不是"现在的时间"。
   - `walk=1s`：等约 1.1 s 再读一次，秒差落在 1..3。**这是把"寄存器能读"与
     "晶振在振"分开的唯一办法** —— RTC 停振时日历寄存器照样保持上次的值，
     只读一次永远 PASS。三轮都读到 1 s，说明计数链真的在走。
   - 跨复位连续性（本轮最有价值的一条）：16:40:29 → 16:41:01 → 16:41:34，
     两次间隔 32 s / 33 s，与三次烧写-复位之间的真实间隔吻合；而首次初始化的
     种子（__TIME__ = 16:40:29）是常量，若每次复位都重设，三行会完全相同。
     所以这三行同时证明了 BKP0R 魔数 + RTCEN 判据生效：**已初始化的 RTC 不被
     重设，日历跨 MCU 复位继续走**（复位不清备份域）。
   - 未验证：**掉电**（VBAT/电池）后的连续性。本板无电池则每次上电都走首次
     初始化路径、日历回到编译时刻 —— 这条没有实测，不能推断。

2) adc raw=988 cal=935/1205 t=45.7C
   - `cal=935/1205`：系统存储区 TS_CAL1/TS_CAL2（0x1FFF7A2C/2E）读到了出厂
     两点校准值（30 °C / 110 °C），自洽（cal110 > cal30、非空片值）。
   - `raw=988 > cal30=935` → 换算 45.7 °C，落在物理区间 [-40,125] 内。
   - 三轮 984→988→990（44.5→45.7→46.2 °C）：raw 单调微升，与"连续烧写、
     芯片自热"一致；这不是判据的一部分，只是现象记录。
   - 判据不包含"等于室温"：板子在机箱内、刚上电，实际环境温度未知，拿室温当
     判据只会得到假 FAIL。这里验的是通道通、校准值读得到、换算走得通。

3) crc 0x4c40e0d7 expect=0x4c40e0d7
   - 输入 4 个整字 {0x31323334, 0x35363738, 0x9ABCDEF0, 0x13579BDF}，
     硬件单元结果与**写死在 board_post.c 里的期望值**逐位相同。
   - 期望值的来源是独立的纯软件位运算实现（poly 0x04C11DB7 / init 0xFFFFFFFF /
     不反射 / 不取反 = CRC-32/MPEG-2），在写代码时用一条 Python 脚本算出
     （4C40E0D7），不是 CRC 单元自己算的。否则这一项就是"我自己等于我自己"，
     只能证明单元可读，不能证明它算得对。
   - 能抓到的故障形态：CRCEN 没开（DR 读回常量 0xFFFFFFFF）、CR.RESET 没做导致
     跨次累积、输入被当字节流处理。

4) rng n=16 distinct=16 degen=0
   - 16 次读都拿到 DRDY（说明 PLL48CK 在 —— 本工程 PLLQ=7 → 336/7 = 48 MHz），
     种子错误位 SECS 未出现。
   - 去重 16/16：16 个 32 位值一次没撞，符合真随机；`degen=0` 表示没有出现
     0x00000000 / 0xFFFFFFFF（这两个正是"单元没使能、DR 停在复位值"的产物）。
   - 这不是随机性测试（那要 NIST 套件），只是"单元活着"的判据。


==========================================================
三、开工核对抓到的问题（表内矛盾，按门槛为准）
==========================================================

`docs/design/功能实现对照表.md` §1.4 原来给 ADC / RNG / CRC 编了枚举
（`BSL_DEV_ADC` / `BSL_DEV_RNG` / `BSL_DEV_CRC`）和 compatible（`brd,rng` /
`brd,crc`），但**同一节的「注册门槛」段落**明确写着："只用于自检的（RNG/CRC/
DAC 等）留在 board_post.c 里直读寄存器，不占设备枚举"。

两处互相矛盾，取舍依据是门槛：注册一个只有 POST 消费的设备，等于造一个
"注册了没人用"的面子接口 —— 这正是本项目一直在删的东西（详见
bsl_device_api.h 里被删掉的 `bsl_debug_uart_api_t` 注释）。处理：

  - ADC / RNG / CRC：**不进** bsl_dev_id_t，不建 DTS 节点（RNG/CRC 是片内固定
    基址，本来就不是板级事实）；
  - RTC：**进**枚举（POST 消费 `bsl_devapi_rtc()`，将来 app_calendar 换墙钟
    也走它 —— 有第二个消费者，符合门槛）；
  - 四项都做成 POST **内置项**，不占已满的 4 个外部名额（font/fatfs/ui/menu）。

同步改了 §1.4 三行、§1.1 新增第 22 行（`crc` / `rng` 是参考工程没有的自研项，
按登记规则只能落在 21 行之后）。


==========================================================
四、实现中的三个硬点（换个人写大概率会踩）
==========================================================

1) 改 RTC 时钟源必须先复位备份域
   RM0090 §5.3.7：RTCSEL 的写入只有在备份域复位后才生效。代价是 BKP 与日历
   寄存器全清。所以初始化分成两条路：
     - RTCEN 已开 + RTCSEL 非 0 + BKP0R 有魔数 → 视为"在走"，只做同步、绝不重设；
     - 否则 → BDRST 脉冲 → 选源（LSE 3 s 超时 → LSI 500 ms）→ 写 PRER/TR/DR
       → 写魔数。
   本轮三行时间跨复位递增，正是第一条路径生效的证据（见判二·1）。

2) PRER 不能写死 32768
   `lse-frequency` 是 DTB 里的板级事实（换板可能是 32.000 kHz）。同步分频按
   `PREDIV_S = f/128 - 1` 算：32768 → 255。写死 255 在 32.000 kHz 板上就是
   每天慢 37 分钟，而现场只会觉得"这钟不准"。

3) ADC 时钟必须 /4，不能 /2
   APB2 = 84 MHz，ADCCLK 上限 36 MHz。ADCPRE=01（/2）= 42 MHz 超限，
   必须 10（/4）= 21 MHz。内部温度通道另需 ≥10 µs 采样（21 MHz 下 480 周期
   = 22.9 µs）。这两条任一条写错，表现为"温度读数偏低/抖动"，不像配置错误。

4) 另外两处编译期坑（本轮实际踩到并已修）
   - bsl_err.h 原来没有"未初始化"这一码。RTC 的"源起不来"（TIMEOUT）与
     "没跑过 init"（NOINIT）必须分开，否则现场无法区分晶振坏与驱动没跑到。
     新增 `BSL_ERR_NOINIT = -5`。
   - bsl_rtc.c 起草时留了一份未使用的 `static const bsl_rtc_api_t s_api`，
     `-Werror=unused-variable` 下直接编译失败；同时 `bsl_rtc_api_t` 的四个成员
     与导出符号必须一一对应，不能"头里有、镜像里没有"。

==========================================================
六、未覆盖 / 遗留（不掩盖）
==========================================================

- **LSI 降级路径没有实测**：LSE 一次就起振，降级的 500 ms 超时分支、
  `src=lsi` 的打印形态都是代码推算，没有上板证据。要验只能拔/短晶振，属破坏性
  操作，本轮不做。
- **掉电保持没有实测**：跨复位连续已证，跨掉电（VBAT 电池）未证。若板上无电池，
  每次上电日历会回到编译时刻 —— 这不是缺陷，是"没有墙钟来源"的物理事实，
  但必须在文档里写清，不能让人误以为 RTC 会记得真实时间。
- **温度绝对值未标定**：只验了"通道通、校准值在、换算成立"。44.5~46.2 °C 与
  室温的差没有用外部温度计比对，不作为精度结论。
- RTC 的 set / 闹钟 / 唤醒扩展未实现（对照表里也没有对应条目 —— 参考工程的
  综合测试只用到"显示时间"）。
- POST 现在 12 项，启动期多了约 1.1 s（RTC 的走时观测）+ 1 ms（ADC 稳定等待）。
- `app_calendar` 仍用编译时刻，未切到 RTC 墙钟：本轮只把"路"打通（`bsl_devapi_rtc`
  可读）。切换属于应用层改动，且需要先决定"没有电池时日期回到编译时刻是否可接受"。
