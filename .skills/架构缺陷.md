# 架构缺陷（机制台账）

## 文档定位

本文件记录**架构与机制层面**曾出过的问题、修复思路，以及对应的 **verify / gate-selftest 守门**。与分工如下：

| 文档 | 回答什么问题 |
|------|----------------|
| [.skills/工程规格.md](./工程规格.md) | 当前代码与构建**应当怎样**（契约真源） |
| [doc/design/系统设计.md](../doc/design/系统设计.md) 第二部分 | 五层、22 处层边、运行期行为（读者版，部分数字有 `collect_doc_count_errors` 机器校验） |
| 本文 | **为什么**要这样设计、改坏了靠什么会叫、还有哪些敞口 |

主键是**机制名**（例如「panic 记录须在 `.noinit`」），不是对话里出现过的 N1/N7 等编号。编号仅作历史脚注，仓库内无法穷举核对的不写。

**关闭标准**：修复落地，且 `build/build.py gate-selftest` 中**至少有一组**对该机制做过破坏态红测（见 [.skills/工程规格.md](./工程规格.md)「自检」）。仅在正确代码上跑绿，不算证明守门有效。

门禁组名与组数唯一来源：`python build/build.py gate-selftest --list`（当前 **49 组**；CI job 数随组数变化，见 `doc/design/系统设计.md`）。

## 架构域与守门地图

```text
apl/fml/bsl/hal/osl 源码
        │
        ├─ 层依赖 / include / extern 符号 ── collect_layer_dependency_errors ── layer-deps
        ├─ 板级极性 / 按键 / LED 掩码一致 ─── collect_board_polarity_errors ─── board-polarity, board-key
        ├─ panic / fault / 代际清理 / 顺序 ─ collect_fault_* / collect_panic_* ─ fault, panic-*, observ …
        ├─ 堆 / _sbrk / newlib 启动期 ────── collect_heap_* / collect_newlib_preboot ── heap, heap-bound, newlib-preboot
        ├─ 健康水位 / 槽号 / 单写者 ──────── collect_health_* ─────────────────── health, health-slot, health
        ├─ 启动 / IWDG / HAL tick / 档位 ─── collect_boot_init_* / tick-source … ─ boot-init, startup-guard, release-size
        ├─ HAL 模块裁剪 / 断言 / FreeRTOS 单元 ─ collect_hal_* / collect_freertos_unit_* ─ hal-module, hal-assert, freertos-unit
        └─ 生成物 Makefile / 拓扑 / 配置 ─── collect_makefile_* / layout / config … ─ makefile, layout, topology, config

doc/ · .skills/ 文档
        ├─ 路径存在性 ────────────────────── collect_doc_reference_errors ────── doc-reference
        ├─ 规格 / SKILL 与仓库一致 ───────── collect_doc_contract_errors ─────── doc-contract
        └─ 系统设计层边处数五路交叉 ──────── collect_doc_count_errors ──────────（无独立红测组，登记 UNCOVERED）
```

新增 `collect_*_errors` 时：在 `build/verify.py` 注册、`ASSERTION_GROUPS` 挂到对应 `case_*`，并按文末维护规则更新本文。

## 已关闭（按域摘要）

下列机制均已修复，且均有对应门禁或 verify 默认判据；细节与提交哈希见 git 历史，此处只保留**可检索的机制名**。

### 分层与模块边界

- **apl 不得直连 hal**：时钟与 `HAL_Init` 收入 `board_system_init()`，`LAYER_DEPENDENCIES["apl"]` 含 `bsl`；`layer-deps`。
- **fml 收紧为 `bsl + osl`**，禁止偷 include hal；`layer-deps` 第三段。
- **尖括号 include 本仓层头可绕过判定** → 要求改成引号形式；`layer-deps` 第四段。
- **`extern` 声明建立层边但不被 include 扫描** → 符号前缀判定；`layer-deps` 第五段。
- **层头归属误含 `tool/` 下第三方头** → 判定域改为 `STATIC_LIB_DIRS`。
- **FreeRTOS 配置关而 `timers.c` 仍编译** → `config_gated_sources` + `freertos-unit`。
- **fml_panic 归属在 LED 模块** → 独立 `fml_panic.c` + `collect_panic_entry_ownership_errors`；`panic-code`。

### Panic、故障现场与可观测性

- **`.noinit` 持久化 `g_panic_record`**，Reset 不清现场；`noinit`、`record-size`、产物符号断言。
- **六入口先 mask 再写 record**；**report 入口 mask 先于重入闸**（防 HardFault 插队）；`panic-order`、`fault`、`panic-mask`。
- **代际清理、magic/seq 抢写、堆 UNSET 与码 0 混淆**；`observ`、`collect_panic_generation_errors`、`collect_panic_scene_errors`。
- **码 4 两失败点同码** → `board_system_init` 返回 1/2 + `g_boot_stage`（`.noinit`）；`boot-init`。
- **码 7 MSP 栈守卫无任务名** → `osl_panic_stack_guard_report`；`observ`。
- **启动期 IWDG 未 ENABLE 导致 panic 永不复位** → `relax` 末尾 `IWDG_KEY_ENABLE`；`boot-init` 五、六段。
- **panic 期间蜂鸣器常鸣** → `panic_leds` 里 BSRR 静音；`panic-beep`。
- **`g_last_write` 跨复位与 panic 摘要**；`persist-record`、`last-write`、`last-write-size`（编译期尺寸守卫）。
- **三档可观测性宏可被关掉而静默**；`observ`。
- **HAL `USE_FULL_ASSERT` 可被关而静默**；`hal-assert`。

### 内存、链接与镜像体积

- **`_sbrk` 有符号溢出**；`heap`。
- **`_write` / `__malloc_lock` 被 gc 掉**；`write`、`heap`。
- **链接脚本假「整库 DISCARD」** → `LIB_MEMBER_WHITELIST` + `lib-member`、`hard-gate`。
- **发布档 `-Os` 与指令级判据冲突** → 双轨 `_skip_on_release_build()` + `out/object/.buildflags`。
- **`make release` 无 `-B` 假绿**；`release-size`、规格「发布构建」。
- **堆 32 KB 白占** → 16 KB + malloc 失败码 2。
- **CCMRAM 三态不一致**；`ccmram-state`。

### 健康水位与周期任务

- **`vTaskDelay` 周期漂移** → `vTaskDelayUntil` + 基准在循环外；`period`。
- **槽号裸字面量 / 槽号与任务身份**；`health-slot`。
- **堆水位双写者** → 仅 tick hook 写；`health`、`collect_health_writer_errors`。
- **`g_heap_free_min` 未用 UNSET 初始化**；`health-slot`。

### 板级、启动与时基

- **LED/蜂鸣/按键极性与数量**；`board-polarity`、`board-key`。
- **panic LED 掩码与 `led_pin[]` 三套定义**；`board-polarity` 第三段。
- **NVIC ICER 上界 / 异常号未减 16**；`fault`、`panic-mask`。
- **`HAL_GetTick` 时钟切换倒退** → `g_tick_ms` 累加器；`tick-source`。
- **VOSRDY 裸等**；`startup-guard`。
- **`HAL_Init` 返回值丢弃**；`boot-init`。
- **复位原因捕获被第二次 `HAL_InitTick` 覆盖**；`boot-init`（`captured` / CYCCNTENA 守卫）。
- **启动期禁止 newlib 分配**；`newlib-preboot`。

### 构建、生成链、CI 与仓库卫生

- **纯头目录生成 Makefile/Kconfig 噪声**；`layout`。
- **门禁矩阵未上 CI** → `gate-list` + matrix；workflow 不硬编码组名。
- **`verify --artifacts` 无 elf 假绿**；各组 `ensure_artifacts` + `NEEDS_ARTIFACTS` 登记。
- **binutils 不可用导致产物断言雪崩假红**；`artifact_tool_errors` + 主机平台 `tool_binary`。
- **`.gitattributes` / 生成端 CRLF**；`line-ending`、`collect_eol_contract_errors`。
- **文档链接两种写法只校一种**；`doc-reference`。
- **顶层未知目录**；`topology`。
- **Makefile / defconfig / 文档契约** 部分判据；`makefile`、`config`、`doc-contract`。
- **win 杂项目录 `tool/win_x86_64/Drivers/`**（非 OpenOCD 驱动包）已从仓库移除；WinUSB 包仅在 `openocd/Drivers/stsw-link009_v3/`。

## 已知敞口

| 性质 | 机制 | 说明 |
|------|------|------|
| 有意不修 | `_write` / `g_last_write` 非日志通道 | 无串口/SWO 出口，调试器直读；占 64 B |
| 有意不修 | `configUSE_NEWLIB_REENTRANT` | 当前无可重入调用方 |
| 有意不修 | 部分 FreeRTOS 模块零使用 | 关宏不省 Flash，已用白名单守「编了没链」 |
| 有意不加 | `.skills` 里 text 采样数字 | 由人维护采样注释，不设门禁 |
| 跟踪 | 堆 16 KB 余量 | 拍板见下「架构拍板」；收紧仍等板上 `g_heap_free_min` |
| 操作纪律 | Git LFS `pre-push` | push 前须 PATH 含 `git-lfs`，勿长期 `core.hooksPath=""` |
| UNCOVERED | `collect_doc_count_errors` | 破坏形态与 `doc-contract` 同形，未单独建第 50 组 |
| UNCOVERED | `collect_verify_errors` 等组合器 | 判据在子 `collect_*` 内 |

历史编号 **N12** 内容已不可复原，敞口清单保留条目以免假装从未存在。

## 架构拍板（现行决策）

| 议题 | 决策 | 备注 |
|------|------|------|
| **系统时钟** | `SystemClock_Config()` 留在 `hal/chip/startup/src/system_stm32f4xx.c`（HAL RCC）；`board_system_init()` 编排；`apl` 不含 hal 头 | 换板改 hal PLL 参数或 bsl 顺序，不迁到 apl |
| **板载 SDRAM** | 默认**不用**：`DATA_IN_ExtSDRAM` 关、链指仅用片内 192 KB | 启用须 `ld` +（正点原子例程或 `HAL_SDRAM`）+ FMC 宏，见 `搭建环境.md` 不替代板上验收 |
| **CCMRAM** | 默认**不启用**：`/DISCARD/` + `collect_ccmram_state_errors` 三态 | 启用须 startup 拷贝符号与脚本同步 |
| **newlib 堆** | `_sbrk` 窗口 **16 KB** 维持 | 待 `g_heap_free_min` 有板上数据后再收紧（原「待拍板」） |
| **RTOS 门面** | **不**做 `osl_task.h` 包 FreeRTOS | `apl`/`fml` 直接引内核头为有意取舍，见 `系统设计.md` |
| **运行指示灯** | 红/绿互斥，`FML_LED_BLINK_PERIOD_MS = 1000` → **1 s** 切换 | 与 `搭建环境.md` 验收表一致 |

## 维护规则

1. 新增架构风险：先写清**机制**与拟用的 `collect_*` / `gate-selftest` 组；守门未设计完前记入「已知敞口」，不算关闭。
2. 关闭条目：对应组必须在破坏态下**红过**，再从「已知敞口」移除或并入「已关闭」域摘要。
3. 删除某条 `collect_*_errors`：同一提交更新本文，并说明为何风险不再存在。
4. 不编造历史编号；对话里的 Nx 无法与仓库行级对应时，只写机制名。

改构建判据或层图时，同步 [.skills/文档维护.md](./文档维护.md) 与 [工程规格.md](./工程规格.md)。
