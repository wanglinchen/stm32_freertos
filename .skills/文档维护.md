# 文档维护约定

**每次修改实现（代码、生成逻辑、目录约定、链接行为）完成后**，须同步文档，并 **`python3 build/create-project.py verify` 通过**（通常通过 **`update`** 自动执行），避免 `.skills`、`doc/` 与仓库行为不一致。

## 必查清单

| 变更类型 | 更新 `.skills` | 更新 `doc/` |
|----------|----------------|-------------|
| `build/create-project.py`（扫描/链接/Kconfig/Makefile/verify） | [工程规格.md](./工程规格.md) 对应章节；必要时 [设计手稿.md](./设计手稿.md)（含框架图） | [使用说明.md](../doc/使用说明.md) |
| `build/install-toolchain.py` · `set-buildenv.py` | [工程规格.md](./工程规格.md) · 脚本表 | [开发环境配置.md](../doc/开发环境配置.md) |
| 新增/调整层目录、静态库、链接顺序 | [工程规格.md](./工程规格.md)、[SKILL.md](./SKILL.md) 层列表 | [使用说明.md](../doc/使用说明.md) |
| CMSIS 启动 / 复位流程 | [工程规格.md](./工程规格.md) 启动约定 | [使用说明.md](../doc/使用说明.md) |
| 仅改应用/驱动源码、不改构建契约 | 一般不必改规格 | 仅当用户可见行为变化时改 doc |

## 文件职责

- **`.skills/`**：Agent 与维护者用的**规格真源**（与代码对齐；[SKILL.md](./SKILL.md) 为入口）。
- **`doc/`**：给人读的简明说明（命令、安装、日常用法）。
- **`.skills/设计手稿.md`**：搭建与设计 checklist（含工程框架图）；与 [工程规格.md](./工程规格.md) 冲突时**以工程规格为准**。

## 提交流前自检

1. 若动过生成逻辑或层目录：已运行 `python3 build/create-project.py update`（**含自动 verify**），或至少 `verify` 显示「自检通过」。
2. [工程规格.md](./工程规格.md) 中**层目录、链接顺序、排除目录、脚本子命令**（含 `verify`）与 `build/create-project.py` 一致。
3. [SKILL.md](./SKILL.md) 中快速命令与「更新后自检」与当前行为一致。
4. `doc/` 中命令示例与 `--help` 输出一致（若存在 `doc/`）。
5. 新增源文件后 `project_defconfig` / Kconfig 行为已在规格或 doc 中有说明（若影响用法）。

verify 失败时：先修文档或代码，再跑 `update`/`verify`，**不要**在自检未通过时视为任务完成。
