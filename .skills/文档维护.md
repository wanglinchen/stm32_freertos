# 文档维护约定

**每次修改实现（代码、生成逻辑、目录约定、链接行为）完成后**，须同步文档，并让
**`python3 build/build.py update` + `build` 通过**，避免 `.skills`、`docs/` 与仓库行为不一致。

> 2026-11-22 起门禁整体删除（`build/checks/`、`build/verify.py`、`verify` 与 `gate-selftest`
> 子命令、CI 红测矩阵）。本文与 `.skills` 里凡是"`verify` 通过才算完成"的旧口径，
> 一律按"`update` 零诊断 + `build` 零告警"执行，待门禁重建后再恢复。

## 文件职责

- **`.skills/`**：Agent 与维护者用的**规格真源**（与代码对齐；[SKILL.md](./SKILL.md) 为入口）。
- **`.skills/架构缺陷.md`**：架构机制、修复与记录；新增风险、关闭条目按它末尾的维护规则同步。
- **`docs/`**：给人读的简明说明（命令、安装、日常用法）。**禁止** `docs/archive/`：勿恢复或新建该目录下的归档 md；历史用 git，机制用 [架构缺陷.md](./架构缺陷.md)。

## 提交前自检

1. 若动过生成逻辑或层目录：已运行 `python3 build/build.py update`，且没有任何诊断输出
   （dtc 的 Warning 也算失败），并打印了 `apollo.dtb` 的字节数。
2. [工程规格.md](./工程规格.md) 中**层目录、链接顺序、排除目录、脚本子命令**与 `build/build.py` 一致。
3. [SKILL.md](./SKILL.md) 中快速命令与「更新后自检」与当前行为一致。
4. `docs/` 中命令示例与 `--help` 输出一致（若存在 `docs/`）。
5. 新增源文件后 `project/config/stm32f429_defconfig_common`（公共项，`update` 自动重写）与 Kconfig 行为已在规格或 docs 中有说明；要"只在本档生效"的差异写进 `stm32f429_defconfig_<variant>` 的 `USER_CUSTOM` 区。

`update` / `build` 失败时：先修文档或代码再重跑，**不要**在自检未通过时视为任务完成。
