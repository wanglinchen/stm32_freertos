# 文档维护约定

**每次修改实现（代码、生成逻辑、目录约定、链接行为）完成后**，须同步文档，并 **`python3 build/build.py verify` 通过**（通常通过 **`update`** 自动执行），避免 `.skills`、`doc/` 与仓库行为不一致。

## 必查清单

| 变更类型 | 更新 `.skills` | 更新 `doc/` |
|----------|----------------|-------------|
| `build/`（`build.py` CLI + `contracts.py` 常量 / `generate.py` 生成 / `verify.py` 判据 / `build.py` 编译驱动） | [工程规格.md](./工程规格.md) 对应章节（含「工程设计手稿」与框架图） | [搭建环境.md](../doc/design/搭建环境.md) |
| `build/build.py` · `build/environment.py` · `flash/flash.py` | [工程规格.md](./工程规格.md) · 脚本表 | [搭建环境.md](../doc/design/搭建环境.md) |
| 新增/调整层目录、静态库、链接顺序 | [工程规格.md](./工程规格.md)、[SKILL.md](./SKILL.md) 层列表 | [系统设计.md](../doc/design/系统设计.md) |
| CMSIS 启动 / 复位流程 | [工程规格.md](./工程规格.md) 启动约定 | [系统设计.md](../doc/design/系统设计.md)（第一部分） |
| 仅改应用/驱动源码、不改构建契约 | 一般不必改规格 | 仅当用户可见行为变化时改 doc |
| 刷机入口 / `flash/` | [工程规格.md](./工程规格.md) 脚本表 | [搭建环境.md](../doc/design/搭建环境.md) |

## 文件职责

- **`.skills/`**：Agent 与维护者用的**规格真源**（与代码对齐；[SKILL.md](./SKILL.md) 为入口）。
- **`.skills/架构缺陷.md`**：架构机制、修复与**守门**记录；新增风险、关闭条目、删断言都按它末尾的维护规则同步。
- **`doc/`**：给人读的简明说明（命令、安装、日常用法）。**禁止** `doc/archive/`：勿恢复或新建该目录下的归档 md；历史用 git，机制用 [架构缺陷.md](./架构缺陷.md)。
## 提交流前自检

1. 若动过生成逻辑或层目录：已运行 `python3 build/build.py update`（**含自动 verify**），或至少 `verify` 显示「自检通过」。
2. [工程规格.md](./工程规格.md) 中**层目录、链接顺序、排除目录、脚本子命令**（含 `verify`）与 `build/build.py` 一致。
3. [SKILL.md](./SKILL.md) 中快速命令与「更新后自检」与当前行为一致。
4. `doc/` 中命令示例与 `--help` 输出一致（若存在 `doc/`）。
5. 新增源文件后 `project_defconfig_userdebug` / `project_defconfig_user`（USER_CUSTOM 两档同步）与 Kconfig 行为已在规格或 doc 中有说明。

verify 失败时：先修文档或代码，再跑 `update`/`verify`，**不要**在自检未通过时视为任务完成。
