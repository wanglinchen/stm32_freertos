# 缺陷台账

## 为什么主键是"机制"而不是编号

两轮只读普查的编号（第一轮 19 条、第二轮 N1–N17、第三轮 N18–N28）只在对话里交付过，
没有落盘成文件。事后想按编号回查时，仓库里查不到字面定义：`grep N7` 全仓零命中，
`git log --grep=N7` 零命中，提交信息也从不带编号。所以这份台账**以机制为主键**，
编号只保留能确证的（N1、N2、N9、N18、N21、N22、N23、N25、N26，以及仍未修的 N12、N17、
N24、N27、N28）。其余编号标「未留存」，不臆造归属——写错的关联比没有关联更坏。

一条缺陷**只有同时具备「机制」和「守门」才算关闭**。守门指仓库里确实存在断言或门禁组，
且 `build/gate-selftest.py` 能在破坏态下让它失败（红测纪律）。只改代码不加守门，
下一次重构就能悄悄改回去，而构建、链接、verify 全都照旧是绿的。

## 判定为良性（不修，只留断言防回归）

| 机制 | 为什么不是缺陷 | 留下的守门 |
|---|---|---|
| 中断优先级无登记表，`vPortValidateInterruptPriority()` 不在镜像（N26） | 自研层 `*FromISR` 命中 0；`port.c` 的 `xPortStartScheduler()` 把 SysTick/PendSV 设成 `0xFF`（最低）、SVCall 设成 `0`；本工程的 `HAL_InitTick()` 覆盖版不碰 SysTick 优先级，所以 `TICK_INT_PRIORITY = 0x0F` 是个没人用的死宏。它随第一个 `*FromISR` 进场才生效，无调用方时被 `--gc-sections` 丢掉是**正确结果** | `collect_isr_priority_errors()`：一旦某文件出现 `*FromISR` / `portYIELD_FROM_ISR`，就要求同文件有 `HAL_NVIC_SetPriority(...)` 且数值 ≥ 5，并要求 `configASSERT` 已定义；门禁组 `isr-prio` 证明它会红 |
| 门禁 `flags` 组的「N 个对象被要求重编」本机 3、Linux 11 | 过期判定基数取决于各自中间态（是否已有完整产物），不是同一棵树，计数不同不影响任何判据 | 需要本机增量证据时先 `clean` 再做对比 |

## 未修 / 待定

| 条目 | 现状与判断 |
|---|---|
| N24 `_write` / `g_last_write` 空壳 | 符号已被 `-Wl,-u,_write` 保住，但函数体什么都不做：一旦有人 printf 仍是静默丢弃。只有接上串口日志才有意义，否则多占 RAM。**建议不动**，先确定日志出口 |
| N27 `USE_FULL_ASSERT` 未开 | `assert_param` 现在是 `((void)0U)`，HAL 的参数检查全部空转。开启前必须先确认一个**非阻塞**失败出口：HAL 里 assert 触发 panic 可能带出递归（panic 内部还会调 HAL） |
| N28 `configUSE_NEWLIB_REENTRANT` 未开 | 多任务共用同一个 `_impure_ptr`（errno / `localtime` 缓冲）。当前没有 newlib 可重入调用方，开了每任务多一个 `_reent`。与 N24 同类，**建议不动** |
| N12 只做一半 | 缺静态断言，只剩口头约定。要补就得先确定它守的是哪条契约 |
| N17 CI cache key 无工具链校验和 | GitHub Actions 的缓存可能命中旧工具链。部分反证：Windows 与 Linux 的 `size` 校验行逐字相同。彻底修需把工具链版本/校验和进 key |

## 未决（需人拍板，不属于缺陷）

- CCMRAM 64 KB 是否启用：链接脚本 `:153-163` 已写明三项前置条件，`/DISCARD/` 目前仍丢 `.ccmram`。
- `-g3` 是否降为 `-g1`、是否引入 ccache：`-g3` 是保留分支 `backup-1f04823` 的存在理由之一。
- 仓库是否转 Private。
- 门禁矩阵是否收紧为只在 `push: main` 跑、PR 上只跑 `build`。
- 本工程仍是**零硬件实测**：168 MHz 起振、USB 枚举、按键/蜂鸣器、IWDG 能否真复位、`.noinit` 跨复位存活、panic 三灯、FPU 扩展帧、`relax` 后 32.7 s 重启循环——目前全部只有静态与反汇编证据。

## 维护规则

1. 新增缺陷先写「机制」与「守门」两栏；守门还没想清楚就先写进「未修」，不要算作已关闭。
2. 只有 `build/gate-selftest.py` 里对应的组**在破坏态下红过**，才算关闭（这也是 TDD 的纪律：断言在正确代码上永远是绿的，绿一次证明不了它会拦人）。
3. 删掉某条断言时，同一提交里必须删掉本台账对应行，并说明为什么不再需要它。
4. 编号对照只在能确证时填写；不确定就写「未留存」，不要为了整齐去猜。
