# STM32F429 系统存储器自举

来源是 `STM32系统存储器启动模式.pdf`，即 AN2606，文档 ID 13801，第 16 版，2013 年 2 月，119 页。原文已经是中文。

这一版的适用表没有 STM32F429。F42x/F43x 只在第 18 章写了 STM32F427xx/F437xx。F429 和它们同代，器件 ID 同为 `0x419`，系统存储器同样从 `0x1FFF0000` 开始。下面按第 3、18、19、20 章把这一代自举程序写全，供 F429 对照。芯片若烧的是更新的 Bootloader，接口会比这里多，以新版 AN2606 为准。

命令的字节格式不在这份应用笔记里。USART 在 AN3155，CAN 在 AN3154，USB DFU 在 AN3156。第 20.3 节的 I2C 时序是给带 I2C 自举的其它型号用的，F427/F437 这一章没有 I2C，也没有 SPI。

## 1 进入和退出

第 3.1 节。配置 BOOT 引脚后执行复位，自举程序才会跑起来。引脚在 SYSCLK 的第四个上升沿锁存。

| BOOT1 | BOOT0 | 启动区 |
| --- | --- | --- |
| 任意 | 0 | 用户 Flash |
| 0 | 1 | 系统存储器 |
| 1 | 1 | 内置 SRAM |

F4 的 BOOT1 是引脚。F05x 和 F3xx 才把 BOOT1 放在选项字节的 nBoot1 位里，那条规则不要套到 F429 上。

第 3.1 节还说：有些带双区自举的产品，在 BOOT0 = 0 时也能进入自举程序，细节要看该产品自己的章节。第 18 章没有写 F427/F437 的双区进入方法，所以不能从这份笔记推出 F429 的双区自举步骤。

退出只能靠硬件复位。复位期间把 BOOT 设成要进的模式。复位后 CPU 从 `0x00000000` 取指。用 Go 命令跳进 Flash 不会改变 BOOT 引脚的选择。

工作温度超出范围时，HSI 随温度漂移，串行协议的时钟会坏，自举程序可能不能用。

## 2 这一版的标识

第 3.3 节把自举程序分成两个编号。

协议版本用 Get Version 命令读，表示某一种接口的通信协议版本。F427/F437 是：

| 接口 | 协议版本 |
| --- | --- |
| USART | V3.1 |
| CAN | V2.0 |
| DFU | V2.2 |

自举程序 ID 是一个字节，形式 `0xXY`。X 表示带哪些接口，Y 是该器件自举程序的版本：

| X | 接口组合 |
| --- | --- |
| 1 | 只有一个 USART |
| 2 | 两个 USART |
| 3 | 两个 USART、一个 CAN、DFU |
| 4 | 两个 USART 和 DFU |
| 5 | 两个 USART 和 I2C |

F427/F437 的接口正是 X = 3 这一档。表 3 把这一行的自举程序 ID 写成 V3.0，字节放在系统存储器最后一个地址减 1，即 `0x1FFF76DE`。可以用 Read Memory 读这个地址，也可以用调试器直接看系统存储器。

表 41 对 V3.0 的说明是「初始版本」。已知限制：读保护有效时，USART 的 Read Memory 和 Write Memory 会连发两个 NACK，而不是一个。

表 42 里这一行的产品 ID 是 `0x419`。Get ID 命令返回的就是这个值。

## 3 用到的硬件

第 18.1 节表 39。进入系统存储器后，自举固件会占用下面这些资源。

所有接口都一样的部分：

| 资源 | 状态 | 说明 |
| --- | --- | --- |
| RCC，HSI | 使能 | 检测阶段和最终选中 USART 时，用 HSI 做 PLL 的时钟源，系统时钟 24 MHz |
| RCC，HSE | 使能 | 只有选中 CAN 或 DFU 之后才改用 HSE。频率必须是 1 MHz 的整数倍，范围 4 MHz 到 26 MHz |
| CSS | 中断使能 | 仅 CAN 和 DFU。外部时钟故障或被拔掉就产生系统复位 |
| RAM | 占用 | 从 `0x20000000` 起的 8 KB 归自举固件，主机不要往这里写 |
| 系统存储器 | 占用 | 从 `0x1FFF0000` 起 30424 字节是自举固件 |
| IWDG | 改配置 | 预分频设成最大值，并定期喂狗。只在选项字节已经打开硬件看门狗时才有意义 |
| 电源 | 改配置 | 电压范围设成 [1.8 V, 2.1 V]。这个范围里内部 Flash 只能按字节写，不能按半字、字或双字写。运行中可以用命令改范围，见第 7 节 |

各接口自己的引脚：

| 接口 | 资源 | 配置 |
| --- | --- | --- |
| USART1 | 外设 | 使能。8 位数据，偶校验，1 个停止位 |
| USART1 | PA10 | RX，输入 |
| USART1 | PA9 | TX，输出 |
| USART3，PB 组 | 外设 | 使能。同样是 8E1 |
| USART3，PB 组 | PB11 | RX，输入 |
| USART3，PB 组 | PB10 | TX，输出 |
| USART3，PC 组 | 外设 | 使能。同样是 8E1 |
| USART3，PC 组 | PC11 | RX，输入 |
| USART3，PC 组 | PC10 | TX，输出 |
| USART1 和 USART3 | SysTick | 使能，用来测主机波特率 |
| CAN2 | 外设 | 使能。125 kbps，11 位标识符。F4 上 CAN2 和 SRAM 的通信由 CAN1 管理，所以 CAN1 的时钟也要开着 |
| CAN2 | PB5 | RX，输入 |
| CAN2 | PB13 | TX，输出 |
| DFU | USB OTG FS | 使能，强制设备模式，并打开 OTG FS 中断 |
| DFU | PA11 | DM，输入 |
| DFU | PA12 | DP，输出 |
| DFU 和 CAN | TIM11 | 使能，用来测外部时钟频率。测完后 RCC 把系统时钟改到后续运行所需的频率 |

检测阶段，没有被当前接口使用的 RX 脚必须保持确定的高或低，不能悬空。表 39 的原话是「高电平或低电平」，第 18.2 节又强调不得悬空。

| 正在使用 | 必须夹住的脚 |
| --- | --- |
| USART1 | PB11、PC11、PB5、PA11、PA12 |
| USART3（PB10/PB11） | PA10、PC11、PB5、PA11、PA12 |
| USART3（PC10/PC11） | PA10、PB11、PB5、PA11、PA12 |
| CAN2 | PA10、PB11、PC11、PA11、PA12 |
| DFU | PA10、PB11、PC11、PB5 |

DFU 依赖 HSE。HSE 数值是用 HSI 测出来的。HSI 因为温度等原因偏离大约 1% 的标称精度时，算出来的 HSE 是错的，DFU 会故障，甚至完全不工作。

USART 全程可以只用 HSI，不需要晶振。HSI 也用于 CAN 和 DFU 的选择阶段。一旦选定 CAN 或 DFU，就必须有合格的 HSE，否则行为异常；图 16 上没有 HSE 时直接系统复位。

测频只能认出 1 MHz 整数倍、且落在 4 MHz 到 26 MHz 的时钟。25 MHz 在这个集合里，24 MHz、8 MHz 也在。25.000 以外的任意值，例如 8.192 MHz，不适用。

18.2 节有一句要求把 USART2 接到 PD6/PD5。本章支持的接口和表 39 都没有 USART2，这句是从别的型号带过来的，F427/F437 不要接。

物理连接：

- USART 经过 RS-232 收发器，例如 ST3232。USART1 接到 PA10 和 PA9。CK、CTS、RTS 都不参与自举，可以留给应用程序。USART3 同样不用这些控制脚。
- 可以用计算机串口小程序，经全零调制解调器电缆，用 CTS 控制 BOOT0、用 DCD 控制复位。STM324x7I-EVAL 板带了这套电路。
- CAN 收发器直接接到 PB5 和 PB13。
- USB 用经过认证的电缆，可以加 ESD 保护。

## 4 接口怎么被选中

第 18.3 节和图 16。固件在循环里查这些接口，先命中的那个被选中，然后其余接口都关掉。选定 USART 或 CAN 之前，USB 主机不能已经连在接口上。选定之后再插 USB 电缆，不会改掉当前接口，除非后续命令本身造成系统复位。

图 16 的实际顺序和上次笔记里写的不一样。复位后的顺序是：

1. 系统初始化：时钟、GPIO、IWDG、SysTick。
2. 先把 USB OTG FS 配成设备。这一步在检测循环之前，不是等到发现电缆才做。
3. 进入循环，按下面的顺序查。

| 顺序 | 条件 | 成立之后 |
| --- | --- | --- |
| 1 | USART1 收到 `0x7F` | 禁止全部中断源，配置 USART1，进入 `BL_USART_Loop` |
| 2 | USART3（PB10/PB11）收到 `0x7F` | 禁止全部中断源，配置 USART3，进入 `BL_USART_Loop` |
| 3 | USART3（PC10/PC11）收到 `0x7F` | 与上一行相同 |
| 4 | CAN2_RX（PB5）上出现帧 | 检查 HSE。有合格 HSE：禁止全部中断源，系统时钟改成 60 MHz，配置 CAN，进入 `BL_CAN_Loop`。没有 HSE：系统复位 |
| 5 | 检测到 USB 电缆 | 检查 HSE。有合格 HSE：系统时钟和 USB 时钟都改成 48 MHz，用 USB 中断执行 DFU。没有 HSE：系统复位 |
| 都没有 | 回到第 1 步继续查 | |

表 39 写「选中 CAN 或 DFU 后系统时钟等于 60 MHz」。图 16 把两条路径分开了：CAN 是 60 MHz，USB 是 48 MHz。以图为准。

USART 路径：主机把串口接到要使用的那一组脚，发出 `0x7F`。固件做完自动波特率，就停在命令循环里等后续命令。

CAN 路径：电缆接到 CAN2。在 PB5 上看到帧之后，才开始测 HSE。HSE 不是 1 MHz 的整数倍，或不在 4–26 MHz，固件会停在循环里继续等消息；完全没有外部时钟则系统复位。

USB 路径：检测循环里一旦发现电缆插入，就进入 DFU 命令循环。

Go 命令跳进用户程序之前，表 39 里这些外设寄存器不会恢复成复位默认值。应用程序要自己重新配置。如果应用程序使用 IWDG，必须把预分频从自举程序留下的最大值改回来。

## 5 能访问的存储器

第 18.4 节和表 42。除了内部 Flash、内部 SRAM、选项字节和系统存储器，还支持 OTP。

| 区域 | 地址 | 说明 |
| --- | --- | --- |
| 主机可写的 RAM | `0x20002000`–`0x20030000` | 开头 8 KB 被自举固件占用，不在这个范围里 |
| Flash | `0x08000000`–`0x08200000` | 24 个扇区：8 个 16 KB、2 个 64 KB、14 个 128 KB |
| 选项字节 | `0x1FFFC000`–`0x1FFFC00F`，以及 `0x1FFEC000`–`0x1FFEC00F` | 两个区，各 16 字节 |
| 系统存储器 | `0x1FFF0000`–`0x1FFF77FF` | Read Memory 允许读到这里。其中从 `0x1FFF0000` 起的 30424 字节是固件本身 |
| OTP | `0x1FFF7800`–`0x1FFF7A0F` | 528 字节。可以读、可以写，Erase 命令擦不掉 |

OTP 的最后 16 字节是保护位。写某个 OTP 单元之前，对应保护位不能处于锁定状态。

选项字节有级别 0、级别 1、级别 2。读保护命令把保护设成级别 1，解除读保护命令把保护设成级别 0。这一章没有展开级别 2 的效果。

整片擦除比小容量 STM32 久，因为 Flash 更大。主机发出擦除命令后，等 ACK 的时间要留够。

如果程序不是放在 `0x08000000`，跳进去之前要把向量表指到实际的加载地址。程序放在 `0x08000000` 且要用中断时，也要在开中断之前完成向量表的映射。F1 超大容量那一章写的是改 `SYSCFG_CFGR1` 的 `MEM_MODE`，那是 F1/F3 的寄存器，不要照抄到 F429。F429 用 SCB 的 VTOR。

## 6 电压范围

每次复位进入自举程序，电压范围都回到默认的 [1.8 V, 2.1 V]。在这个范围里只能按字节写内部 Flash。

范围可以通过一块 4 字节的虚拟单元修改。它不是真正的存储器，USART、CAN、DFU 都用普通的读/写命令访问。支持 1、2、3 或 4 字节访问。保留字节必须保持 `0xFF`，否则这次请求得到 NACK。

| 地址 | 长度 | 取值 |
| --- | --- | --- |
| `0xFFFF0000` | 1 字节 | `0x00`：[1.8 V, 2.1 V]。`0x01`：[2.1 V, 2.4 V]。`0x02`：[2.4 V, 2.7 V]。`0x03`：[2.7 V, 3.6 V]。`0x04`：[2.7 V, 3.6 V]，并且允许双字写和擦除，此时 VPP 脚要供 9 V，步骤见 PM0081。其它值 NACK |
| `0xFFFF0001` | 1 字节 | 保留，必须是 `0xFF` |
| `0xFFFF0002` | 1 字节 | 保留，必须是 `0xFF` |
| `0xFFFF0003` | 1 字节 | 保留，必须是 `0xFF` |

F429 板子若是 3.3 V 供电，按字写 Flash 之前先把 `0xFFFF0000` 写成 `0x03`。不要写 `0x04`，除非板上真的给 VPP 加了 9 V。

## 7 主机等待时间

第 20 章。时间单位是毫秒。这些数用来设置主机的连接超时。三类时间来源不同：数据手册里的硬件时间、由波特率和主机决定的通信时间、自举软件自己的执行时间。

F427/F437 的这些时间与 HSE 频率无关。HSE 是用 TIM11 对 HSI 做周期测量得到的。

### 7.1 USART

图 17。时序 A 是复位完成到主机可以发 `0x7F`。时序 B 是 `0x7F` 发出去之后，到收到第一个 ACK。

波形从左到右是：复位、HSI 起振、器件稳定、自举软件准备、PLL 锁定，然后主机发 `0x7F`，自举程序测波特率并回 ACK。

| 符号 | 含义 | 最小 | 最大 |
| --- | --- | --- | --- |
| a | 复位持续时间 | 0.5 | 3.0 |
| b | HSI 起振 | 0.0022 | 0.004 |
| c | 自举固件操作 | 0.0089 | — |
| d | PLL 锁定 | 0.075 | 0.2 |
| e | 自举固件操作，到可以接收 `0x7F` | 81.047 | — |
| f | 发送一个 USART 字节。最小按最高波特率，最大按 9600 左右的低波特率 | 0.078125 | 7.5 |
| g | 收到 `0x7F` 之后的固件操作 | 0.0058 | — |
| A | a + b + c + d + e，发 `0x7F` 之前至少要等这么久 | 81.6331 | 84.2599 |
| B | 2×f + g，等第一个 ACK | 0.16205 | 15.0058 |

主机侧按最大值留余量：复位后至少等 85 ms 再发 `0x7F`，再留 15 ms 等 ACK。

### 7.2 USB

时序 A 与 USART 相同，是复位后到主机可以开始连接序列。时序 B 是开始连接之后，器件完成枚举和 DFU 配置、可以接收命令的时间。

USB 的连接时间受集线器层数、主机速度和总线负载影响，所以表 66 只给最短值。

| 符号 | 含义 | 最短 |
| --- | --- | --- |
| a | 复位 | 0.5 |
| b | HSI 起振 | 0.0022 |
| c | 自举固件 | 0.0089 |
| d | PLL 锁定 | 0.075 |
| e | 自举固件 | 81.047 |
| A | a+b+c+d+e | 81.6331 |
| B | 建立连接 | 773.13 |

互连型 F105/F107 在 HSE 不是 25 MHz 时会反复枚举失败。那条注写在第 20.2 节，针对的是互连型，不是 F427/F437。F427/F437 用 TIM11 测 HSE，不靠 SOF。
