## 1 关于本文档

读者是做应用和系统软件的人，不要求事先用过 Arm。排版约定：尖括号表示汇编里要替换的操作数，等宽字体表示可输入的代码。寄存器访问类型：

| 缩写 | 含义 |
| --- | --- |
| rw / RW | 软件可读写 |
| r / RO | 只读 |
| w / WO | 只写，读回复位值 |

### 1.1 内核在 STM32 里的位置

Cortex-M4 是面向微控制器的 32 位处理器，使用基于 Thumb-2 的 Thumb 指令集。STM32 上的这颗内核带单精度 FPU。手册列出的特点：

- 处理性能和中断响应做在一起：硬件压栈，可打断正在进行的多寄存器加载/存储，ISR 不需要汇编桩
- 尾链（tail-chaining）减少从一个 ISR 切到下一个 ISR 的开销
- 硬件除法、快速乘法
- 集成睡眠，`SLEEPDEEP` 配合 WFI 可进入 STM32 的 Stop 或 Standby
- MPU 按区域保护代码、数据和栈
- 调试口可以是 JTAG 或两线 SWD；跟踪可以走 SWV，可选 ETM

系统接口使用 AMBA，支持非对齐数据访问，并用位带（bit-band）做原子的位操作。

### 1.2 内核对外设一览

| 外设 | 作用 |
| --- | --- |
| NVIC | 嵌套向量中断控制器，低延迟处理中断 |
| SCB | 系统控制块：实现信息、系统异常的配置和状态 |
| SysTick | 24 位递减定时器，常做 RTOS 节拍 |
| MPU | 最多 8 个区域，外加可选的背景区域。具体型号是否带 MPU 以数据手册为准；STM32F429 带 MPU |
| FPU | IEEE 754 单精度（32 位）浮点。手册写明所列 STM32 Cortex-M4 微控制器都实现了 FPU |

## 2 Cortex-M4 处理器

### 2.1 程序员模型

#### 2.1.1 模式与特权级

| 模式 | 用途 | 特权 | 栈 |
| --- | --- | --- | --- |
| 线程模式 Thread | 跑应用。复位后进入此模式 | 由 CONTROL 决定，可以是特权或非特权 | MSP 或 PSP，由 CONTROL 决定 |
| 处理模式 Handler | 跑异常处理函数。异常结束后回到线程模式 | 始终特权 | 始终 MSP |

非特权软件：

- MSR/MRS 只能访问有限寄存器，不能用 CPS
- 不能访问 SysTick、NVIC、SCB
- 存储器和外设访问可能被 MPU 限制
- 要进入特权代码，执行 SVC

特权软件可以使用全部指令和资源，并可以写 CONTROL 来改变线程模式的特权级。

#### 2.1.2 栈

满递减栈：SP 指向最后压入的那个数据。压栈时先把 SP 减 4，再写入。

两套栈指针：主栈 MSP、进程栈 PSP。线程模式用哪一套由 CONTROL[1] 决定。复位值是 MSP。复位时从地址 `0x00000000` 取出 MSP 初值。

#### 2.1.3 内核寄存器

| 名称 | 访问 | 所需特权 | 复位值 | 说明 |
| --- | --- | --- | --- | --- |
| R0–R12 | 读写 | 均可 | 未知 | 通用寄存器 |
| MSP（R13） | 读写 | 特权 | 来自向量表首字 | 主栈指针 |
| PSP（R13） | 读写 | 均可 | 未知 | 进程栈指针 |
| LR（R14） | 读写 | 均可 | `0xFFFFFFFF` | 链接寄存器，也保存异常返回码 |
| PC（R15） | 读写 | 均可 | 复位向量 | 复位时从 `0x00000004` 取 PC，该值的 bit0 写入 EPSR.T，必须为 1 |
| PSR | 读写 | 特权 | `0x01000000` | APSR + IPSR + EPSR |
| APSR | 读写 | 均可 | 未知 | 条件标志 |
| IPSR | 只读 | 特权 | `0x00000000` | 当前异常号 |
| EPSR | 只读 | 特权 | `0x01000000` | 执行状态，复位时 T=1 |
| PRIMASK | 读写 | 特权 | 0 | 屏蔽可配置优先级异常 |
| FAULTMASK | 读写 | 特权 | 0 | 屏蔽除 NMI 以外的所有异常 |
| BASEPRI | 读写 | 特权 | 0 | 屏蔽优先级数值大于等于该值的异常 |
| CONTROL | 读写 | 特权 | 0 | 特权级、栈选择、FPU 上下文 |

含保留位的完整定义在 [5.1](#51-内核寄存器)。下面先列常用位。

PSR 是三组互斥位域拼成的 32 位寄存器。用 MRS/MSR 时可以按组合名访问：

| 名字 | 组合 |
| --- | --- |
| PSR | APSR + EPSR + IPSR |
| IEPSR | EPSR + IPSR，只读 |
| IAPSR | APSR + IPSR |
| EAPSR | APSR + EPSR |

写 IPSR 被忽略。读 EPSR 得到 0，写 EPSR 被忽略。写条件标志时用 `APSR_nzcvq`。

APSR 主要位：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 31 | N | 负数 |
| 30 | Z | 结果为 0 |
| 29 | C | 进位或借位 |
| 28 | V | 溢出 |
| 27 | Q | 饱和，DSP 指令把结果饱和时置位 |
| 19:16 | GE[3:0] | 大于或等于，SIMD 比较的逐通道标志 |

IPSR[8:0] 是 `ISR_NUMBER`，即当前异常号。线程模式为 0。

EPSR：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 26:25、15:10 | ICI/IT | 可继续的多寄存器传送，或 IT 块状态 |
| 24 | T | Thumb 状态。必须为 1，清 0 会进入 UsageFault（或升级为 HardFault） |

异常屏蔽寄存器（都要特权）：

| 寄存器 | 作用 |
| --- | --- |
| PRIMASK[0] | 1：不响应所有可配置优先级的异常。NMI 和 HardFault 不受影响 |
| FAULTMASK[0] | 1：除 NMI 外全部不响应。优先级相当于 -1，但 HardFault 本身仍可在故障升级时发生。异常返回时硬件清 0，也可以用 CPS 清 |
| BASEPRI[7:0] | 0：不屏蔽。非 0：不处理优先级数值大于等于该字段的异常。数值越大优先级越低。本手册写明可配置优先级范围是 0–15，只用高 4 位，写 BASEPRI 时要左移到 bit[7:4] |

CONTROL：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | nPRIV | 0：线程模式为特权（复位值）。1：线程模式为非特权。只有特权软件能写 |
| 1 | SPSEL | 0：线程模式用 MSP（复位值）。1：用 PSP。处理模式忽略此位，始终用 MSP |
| 2 | FPCA | 1：当前上下文含浮点状态，异常进入时分配浮点栈帧。由硬件在执行浮点指令时置位 |

#### 2.1.4 异常、数据类型、CMSIS

异常和中断的编号见 [2.3](#23-异常模型)。

数据类型：字 32 位，半字 16 位，字节 8 位。存储器为小端。

CMSIS 是内核的 C 接口。本工程的寄存器定义在 `hal/arch/inc/core_cm4.h`，异常号在 `hal/chip/register/inc/stm32f429xx.h` 的 `IRQn_Type`。

### 2.2 存储器模型

地址空间 4 GB，映射固定。MPU 可以改写默认属性。

| 地址 | 区域 | 默认类型 | XN | 说明 |
| --- | --- | --- | --- | --- |
| `0x00000000`–`0x1FFFFFFF` | Code，1 GB | Normal | 否 | 放程序，也可以放数据。指令和数据走不同总线，程序放这里才能并行取指和访存 |
| `0x20000000`–`0x3FFFFFFF` | SRAM，1 GB | Normal | 否 | 数据，也可以放代码。最低 1 MB 是位带区 |
| `0x40000000`–`0x5FFFFFFF` | 片上外设，0.5 GB | Device | 是 | GPIO、USART 等。最低 1 MB 是位带区 |
| `0x60000000`–`0x9FFFFFFF` | 外部 RAM，1 GB | Normal | 否 | FSMC/FMC 映射的外部存储器 |
| `0xA0000000`–`0xDFFFFFFF` | 外部设备，1 GB | Device | 是 | 外部设备区 |
| `0xE0000000`–`0xE00FFFFF` | 内核私有外设总线 PPB | Strongly-ordered | 是 | NVIC、SysTick、SCB、MPU、FPU |
| `0xE0100000`–`0xFFFFFFFF` | 厂商保留 | Device | 是 | 含调试等系统地址，具体见参考手册 |

三种存储器类型：

| 类型 | 行为 |
| --- | --- |
| Normal | 可以重排、可以推测读，用来提速 |
| Device | 相对其他 Device 和 Strongly-ordered 访问保持顺序。写可以缓冲 |
| Strongly-ordered | 相对所有其他访问保持顺序。写不能缓冲 |

XN（Execute Never）：禁止取指。从 XN 区取指产生 MemManage fault。

默认顺序（程序顺序里 A1 在 A2 之前）：

| 先访问 \ 后访问 | Normal | Device 非共享 | Device 共享 | Strongly-ordered |
| --- | --- | --- | --- | --- |
| Normal | 不保证 | 不保证 | 不保证 | 不保证 |
| Device 非共享 | 不保证 | 按程序顺序 | 不保证 | 按程序顺序 |
| Device 共享 | 不保证 | 不保证 | 按程序顺序 | 按程序顺序 |
| Strongly-ordered | 不保证 | 按程序顺序 | 按程序顺序 | 按程序顺序 |

内核会预取指令，也会对分支目标做推测预取。

#### 2.2.1 屏障指令

顺序对结果有影响、而硬件又不保证时，要自己插入屏障。访问 SCB 这类 Strongly-ordered 地址时，不需要为它单独加 DMB。

| 指令 | 作用 | 典型场合 |
| --- | --- | --- |
| DMB | 后面的存储器事务开始前，前面的存储器事务已经完成 | 改向量表后再使能异常；多主设备上的信号量之后 |
| DSB | 后面的指令执行前，前面的存储器事务已经完成 | 切换存储器映射之后；异常已经挂起或正在处理时改它的优先级；MPU 编程序列里跟在 ISB 前面 |
| ISB | 后面的指令能看到此前已完成事务的效果 | 自修改代码之后；MPU 配置之后（DSB 然后 ISB，或靠异常返回） |

#### 2.2.2 位带

SRAM 和片上外设各自最低 1 MB 是位带区，对应 32 MB 的别名区。对别名区的一次字访问，映射成位带区里的一个位。写别名是读-改-写，只看写入值的 bit0：1 把目标位置 1，0 把目标位清 0。高 31 位不影响目标位。别名访问的传输宽度跟发起它的那条指令一致。对别名区取指不会按位带重映射；外设别名区不允许取指。

| 位带区 | 别名区 |
| --- | --- |
| SRAM `0x20000000`–`0x200FFFFF` | `0x22000000`–`0x23FFFFFF` |
| 外设 `0x40000000`–`0x400FFFFF` | `0x42000000`–`0x43FFFFFF` |

```text
bit_word_offset = (byte_offset × 32) + (bit_number × 4)
bit_word_addr   = bit_band_base + bit_word_offset
```

`bit_band_base` 是别名区起始地址，`byte_offset` 是目标字节在位带区内的偏移，`bit_number` 是 0–7。

例子：别名字 `0x2200001C` 对应 `0x20000000` 这个字节的 bit7。`0x22000000 + (0 × 32) + (7 × 4) = 0x2200001C`。

STM32F429 的 AHB 外设大多在 `0x40020000` 以上，不在这 1 MB 位带区里。位带只覆盖 `0x40000000`–`0x400FFFFF`（APB 低段）和 SRAM 低 1 MB。

#### 2.2.3 端序

小端。一个字的最低字节放在最低地址。AIRCR.ENDIANESS 读出为 0，表示小端，软件不能改成大端。

#### 2.2.4 独占访问

LDREX/STREX（以及半字、字节形式）提供不阻塞的读-改-写。STREX 的返回值：0 表示独占成功并完成写，1 表示失败且没有写入。

本地独占监视器会在这些情况下丢掉标记：执行 CLREX、执行任意 STREX（不论成败）、发生异常。异常会清标记，所以不同线程之间的信号量冲突可以靠异常返回后重试来解开。

C 语言不能直接生成这些指令。CMSIS：

| 指令 | CMSIS |
| --- | --- |
| LDREX | `uint32_t __LDREXW(uint32_t *addr)` |
| LDREXH | `uint16_t __LDREXH(uint16_t *addr)` |
| LDREXB | `uint8_t __LDREXB(uint8_t *addr)` |
| STREX | `uint32_t __STREXW(uint32_t value, uint32_t *addr)` |
| STREXH | `uint32_t __STREXH(uint16_t value, uint16_t *addr)` |
| STREXB | `uint32_t __STREXB(uint8_t value, uint8_t *addr)` |
| CLREX | `void __CLREX(void)` |

### 2.3 异常模型

#### 2.3.1 状态

| 状态 | 含义 |
| --- | --- |
| 无效 Inactive | 未挂起，也未在处理 |
| 挂起 Pending | 等待处理。外设或软件都可以把它变成挂起 |
| 有效 Active | 正在被处理，还没结束 |
| 有效且挂起 | 正在处理，同一来源又来了一次 |

嵌套时，被抢占的异常和处理它的异常同时处于有效状态。

#### 2.3.2 异常类型

数值越小优先级越高。除 Reset、NMI、HardFault 以外，优先级可配置，范围 0–15。没有配置时，可配置优先级的异常都是 0。因此三条固定优先级的异常永远高于其余异常。

同优先级的多个挂起异常里，异常号小的先处理。正在执行的处理函数不会被同优先级的新异常抢占；新异常只变成挂起。

| 异常号 | IRQ 号（CMSIS） | 类型 | 优先级 | 向量地址 | 触发 |
| --- | --- | --- | --- | --- | --- |
| 1 | — | Reset | -3 | `0x00000004` | 异步 |
| 2 | -14 | NMI | -2，固定 | `0x00000008` | 异步 |
| 3 | -13 | HardFault | -1，固定 | `0x0000000C` | 故障升级或取向量失败 |
| 4 | -12 | MemManage | 可配置 | `0x00000010` | 同步 |
| 5 | -11 | BusFault | 可配置 | `0x00000014` | 精确时同步，不精确时异步 |
| 6 | -10 | UsageFault | 可配置 | `0x00000018` | 同步 |
| 7–10 | — | 保留 | — | — | — |
| 11 | -5 | SVCall | 可配置 | `0x0000002C` | 同步，由 SVC 指令触发 |
| 12–13 | — | 保留 | — | — | — |
| 14 | -2 | PendSV | 可配置 | `0x00000038` | 异步 |
| 15 | -1 | SysTick | 可配置 | `0x0000003C` | 异步 |
| 16 起 | 0 起 | 外部中断 IRQ | 可配置 | `0x00000040` 起，每项加 4 | 异步 |

CMSIS 只用 IRQ 号，所以系统异常的 IRQ 号是负数。IPSR 返回的是异常号，不是 IRQ 号。STM32F429 的外部中断名和个数以 `IRQn_Type` 为准，不要用手册里某一处举例的上界套到这颗芯片上。

各异常的用途：

| 异常 | 说明 |
| --- | --- |
| Reset | 上电或热复位。复位期间指令可能停在任意点。释放后从向量表的复位项重新开始，特权、线程模式 |
| NMI | 外设或软件触发。除复位外最高。不能被屏蔽，也不能被除复位以外的异常抢占 |
| HardFault | 异常处理过程出错，或故障无法由 MemManage/BusFault/UsageFault 承接。优先级 -1 |
| MemManage | MPU 违规，或违反固定的存储器保护（例如从 XN 区取指）。复位后默认关闭，要在 SHCSR 里打开 |
| BusFault | 总线错误。精确的（PRECISERR）在指令边界上报；不精确的（IMPRECISERR）可能晚几个周期 |
| UsageFault | 未定义指令、非法的非对齐访问、执行时 T 位为 0、异常返回错误。打开相应陷阱后，非对齐的字/半字访问、除以 0 也会进来 |
| SVCall | SVC 指令。操作系统里用来从任务进入内核服务 |
| PendSV | 可挂起的系统服务请求。FreeRTOS 用它在没有更高优先级中断时做任务切换 |
| SysTick | 计数到 0，或软件挂起。本工程节拍 1000 Hz，处理函数是 `SysTick_Handler` |
| IRQ | 外设或软件触发，与当前指令异步 |

处理函数分类：IRQ 由 ISR 处理；四种 fault 由 fault handler 处理；NMI、PendSV、SVCall、SysTick 和 fault 都算系统处理函数。

可配置优先级的异常可以被特权软件关掉：系统异常看 SHCSR 的使能位，外部中断看 NVIC_ICERx。

#### 2.3.3 向量表

第一项是 MSP 初值，后面每项是处理函数地址。每一项的最低位必须是 1，表示 Thumb 代码。

复位时向量表固定在 `0x00000000`。特权软件可以写 VTOR，把表挪到 `0x00000080`–`0x3FFFFF80` 范围内的某个地址。对齐要求取决于表里有多少项：偏移必须按异常项数量对齐（见 VTOR 的 TBLOFF 说明）。表项多于 64 个时，工程上通常至少按 512 字节对齐。

改完某一项再使能对应异常之前，要插入 DMB，避免异常立刻发生时还用旧向量。

#### 2.3.4 优先级分组

NVIC 把优先级拆成两段：

- 高位是组优先级（抢占优先级）。只有它决定能不能抢占
- 低位是子优先级。组优先级相同时，用它决定谁先被接受；再相同，则 IRQ 号小的先处理

分组点由 AIRCR.PRIGROUP 决定。本内核只实现优先级的 bit[7:4]，数值 0–15。手册给出的分组（`x` 是组优先级，`y` 是子优先级）：

| PRIGROUP | PRI_N[7:4] | 组优先级位数 | 子优先级位数 | 组数 | 子优先级数 |
| --- | --- | --- | --- | --- | --- |
| 0b0xx | `xxxx` | 4 | 0 | 16 | 无 |
| 0b100 | `xxx.y` | 3 | 1 | 8 | 2 |
| 0b101 | `xx.yy` | 2 | 2 | 4 | 4 |
| 0b110 | `x.yyy` | 1 | 3 | 2 | 8 |
| 0b111 | `.yyyy` | 0 | 4 | 无 | 16 |

FreeRTOS 调用 API 的中断，其抢占优先级数值必须大于等于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`（本工程为 5）。数值更小（优先级更高）的中断不能调用 FreeRTOS API。内核自己的 SysTick、PendSV 放在最低档 15。

#### 2.3.5 进入与返回

术语：

- 抢占：正在处理异常时，来了更高优先级的异常
- 返回：当前处理结束，且没有足够优先级的挂起异常；处理器弹出栈帧，恢复进入前的状态

进入条件：有挂起异常，其优先级高于屏蔽寄存器允许的门槛，并且处理器在线程模式，或者新异常的优先级高于正在处理的异常。

除尾链和晚到之外，进入时硬件把栈帧压到当前栈（线程模式看 SPSEL，处理模式用 MSP）。基本整数帧 8 个字，从低地址到高地址：

| 偏移 | 内容 |
| --- | --- |
| 0x00 | R0 |
| 0x04 | R1 |
| 0x08 | R2 |
| 0x0C | R3 |
| 0x10 | R12 |
| 0x14 | LR（进入前的 R14） |
| 0x18 | 返回地址（PC） |
| 0x1C | xPSR |

使用浮点且需要保留浮点上下文时，在整数帧的低地址一侧再压扩展帧：S0–S15、FPSCR，以及一个对齐保留字。CONTROL.FPCA 表示当前上下文是否含浮点状态。懒压栈（FPCCR.LSPEN）打开时，真正的浮点寄存器可以推迟到处理函数里确实用到 FPU 时再写入栈，入口只分配空间。

返回时把一个 EXC_RETURN 值写入 PC（通常是 `BX LR`，LR 里已经是这个值）。合法值：

| EXC_RETURN | 返回到 | 栈 | 栈帧 |
| --- | --- | --- | --- |
| `0xFFFFFFF1` | 处理模式 | MSP | 仅整数帧 |
| `0xFFFFFFF9` | 线程模式 | MSP | 仅整数帧 |
| `0xFFFFFFFD` | 线程模式 | PSP | 仅整数帧 |
| `0xFFFFFFE1` | 处理模式 | MSP | 含浮点 |
| `0xFFFFFFE9` | 线程模式 | MSP | 含浮点 |
| `0xFFFFFFED` | 线程模式 | PSP | 含浮点 |

bit4 为 0 表示扩展帧，bit2 为 1 表示 PSP，bit3 为 1 表示回到线程模式。

两种硬件优化：

- 尾链：当前异常返回时已经有另一个异常在等。处理器不再把寄存器弹出又压上，直接取下一个向量
- 晚到：压栈过程中来了更高优先级的异常。处理器改为去处理晚到的那个，原先那个保持挂起

除复位以外的异步异常，从触发到进入处理函数之间，处理器还可能再执行一条指令。

### 2.4 故障处理

#### 2.4.1 故障类型

| 故障 | 典型原因 | 默认 |
| --- | --- | --- |
| MemManage | MPU 拒绝访问；栈操作违反 MPU；从 XN 取指 | 关闭，升级为 HardFault |
| BusFault | 总线应答错误；压栈/出栈时总线错；向量读取总线错 | 关闭，升级为 HardFault |
| UsageFault | 未定义指令；非法使用 EPSR；除以 0；非对齐访问 | 关闭，升级为 HardFault |
| HardFault | 上述故障未使能；取向量表失败；在 NMI 或 HardFault 里又故障 | 始终使能，优先级 -1 |

#### 2.4.2 升级与锁定

故障处理函数没有使能，或故障发生时其优先级不够（被 PRIMASK、FAULTMASK、BASEPRI 挡住），就会升级成 HardFault。

锁定（lockup）：在 NMI 或 HardFault 处理过程中又发生无法处理的故障，或在启动阶段 HardFault 无法执行。处理器停止取有用指令，直到复位或调试器介入。调试器停机时能看到 PC 停在一个无法前进的状态。

#### 2.4.3 状态寄存器与地址寄存器

发生故障后先看：

1. HFSR：是向量表错误（VECTTBL）还是被升级来的（FORCED）
2. 若 FORCED=1，再看 CFSR，它由三段拼成：MMFSR（byte0）、BFSR（byte1）、UFSR（高半字）
3. MMFAR / BFAR 只有在对应的 VALID 位为 1 时，里面的地址才有效。读地址之前不要先做会清状态的操作

MMFSR（CFSR 低字节）常用位：IACCVIOL 取指违规，DACCVIOL 数据违规，MSTKERR 进入时压栈违规，MUNSTKERR 返回时出栈违规，MLSPERR 浮点懒压栈违规，MMARVALID 表示 MMFAR 有效。

BFSR 常用位：IBUSERR 取指总线错，PRECISERR 精确数据总线错，IMPRECISERR 不精确数据总线错，STKERR / UNSTKERR 压栈或出栈总线错，LSPERR 懒压栈总线错，BFARVALID 表示 BFAR 有效。

UFSR 常用位：UNDEFINSTR，INVSTATE（例如 T 位为 0 却去执行），INVPC（非法 EXC_RETURN），NOCP（协处理器未使能，最常见是没用 CPACR 打开 FPU 就执行了浮点指令），UNALIGNED，DIVBYZERO。

### 2.5 功耗管理

睡眠由 NVIC 侧的系统控制寄存器配合 WFI/WFE 进入。`SCR.SLEEPDEEP = 0` 是普通睡眠（STM32 上通常是 Sleep，外设时钟还在）。`SLEEPDEEP = 1` 时，WFI/WFE 让 STM32 进入 Stop 或 Standby，具体由 PWR 模块的寄存器决定，那部分在参考手册里，不在 PM0214。

进入：

- 执行 WFI：停住，直到中断、NMI 或复位
- 执行 WFE：停住，直到事件。事件可以是 SEV 指令，或在 SEVONPEND 打开时某个中断变成挂起
- `SCR.SLEEPONEXIT = 1`：异常返回到线程模式时自动睡觉，适合主循环只有中断的程序

唤醒：

- 优先级足够的中断或异常会唤醒并进入处理函数
- 如果该中断被 PRIMASK/BASEPRI 挡住，WFI 仍可能被它唤醒，但醒来后不进 ISR，继续执行 WFI 后面的指令。这是“只唤醒、不响应”的用法
- WFE 配合 SEVONPEND：中断即使没使能，变成挂起也能当作事件

调试器停机时 SysTick 不递减。睡眠期间 SysTick 是否继续走，取决于时钟在该低功耗模式下是否还在。

## 3 指令集

Cortex-M4 执行 Thumb-2：16 位和 32 位 Thumb 指令混排。没有 Arm 状态，EPSR.T 必须保持 1。原手册第 3 章（约第 50–192 页）按条给出语法、编码和操作伪码；下面只保留写 C 和读反汇编时需要的分类、条件码和限制。

### 3.1 操作数约定

- `<cond>` 条件后缀，见下表。不写则 AL，始终执行
- `Rn`、`Rm` 源寄存器，`Rd` 目的寄存器，`Rt` 传送目标
- 第二操作数可以是立即数或寄存器，寄存器还可以再移位
- PC 读出来的值是当前指令地址加 4（字对齐后的流水线偏移）
- 大多数数据处理指令不能把 SP 或 PC 当任意寄存器使用。合法的例外在各条指令里单独规定，例如 ADD/SUB 可以调整 SP，LDR 可以用 PC 做基址，BX 可以用任意寄存器包括 LR

移位：

| 操作 | 行为 |
| --- | --- |
| LSL | 逻辑左移，低位补 0 |
| LSR | 逻辑右移，高位补 0 |
| ASR | 算术右移，高位补符号位 |
| ROR | 循环右移 |
| RRX | 带进位的循环右移一位，C 位移入最高位 |

对齐：字访问地址应 4 字节对齐，半字应 2 字节对齐。未对齐的 Normal 访问多数能由硬件完成，但 LDRD/STRD 以及独占访问要求对齐。未对齐访问若被 CCR 配成陷阱，则产生 UsageFault。Device 存储器上的未对齐访问不要依赖。

PC 相对表达式：汇编器把 `label - PC` 编成立即数偏移。ADR 得到的是字对齐后的 PC 加偏移。

### 3.2 条件执行

| 后缀 | 标志 | 含义 |
| --- | --- | --- |
| EQ | Z=1 | 相等 |
| NE | Z=0 | 不等 |
| CS / HS | C=1 | 无符号大于或等于 |
| CC / LO | C=0 | 无符号小于 |
| MI | N=1 | 负 |
| PL | N=0 | 正或零 |
| VS | V=1 | 溢出 |
| VC | V=0 | 未溢出 |
| HI | C=1 且 Z=0 | 无符号大于 |
| LS | C=0 或 Z=1 | 无符号小于或等于 |
| GE | N=V | 有符号大于或等于 |
| LT | N≠V | 有符号小于 |

| LE | Z=1 或 N≠V | 有符号小于或等于 |

## 4 内核对外设

私有外设总线地址。未列出的调试寄存器不在本手册范围内。

| 地址 | 外设 |
| --- | --- |
| `0xE000E010`–`0xE000E01F` | SysTick |
| `0xE000E100`–`0xE000E4EF` | NVIC |
| `0xE000ED00`–`0xE000ED3F` | SCB |
| `0xE000ED88`–`0xE000ED8B` | CPACR（FPU 协处理器访问控制） |
| `0xE000ED90`–`0xE000EDB8` | MPU |
| `0xE000EF00`–`0xE000EF03` | NVIC_STIR |
| `0xE000EF30`–`0xE000EF44` | FPU 寄存器 |

除特别说明外，这些寄存器只有特权软件能访问。非特权访问产生 BusFault 或 MemManage。

### 4.1 MPU

8 个区域，编号 0–7，另有一个仅特权可访问的背景区域。背景区域的属性和默认存储器映射相同。指令和数据使用同一套区域设置。

区域可以重叠。重叠时编号最大的区域生效，例如区域 7 盖过与它重叠的任何区域。访问被 MPU 拒绝时产生 MemManage；若 MemManage 未使能，则升级为 HardFault。

改完 MPU 后执行 DSB 再执行 ISB，或通过异常返回，后续指令才会使用新配置。更新一个区域时，先把该区域关掉（RASR.ENABLE=0），再写 RBAR 和 RASR，避免中间状态被用到。也可以用 RBAR 的 VALID 和 REGION 字段，在一次写 RBAR 时顺带选择区域号。

#### 4.1.1 区域属性

SIZE 字段编码的是 `2^(SIZE+1)` 字节，最小可配置区域通常是 32 字节（SIZE=4）。基址必须按区域大小对齐。每个区域分成 8 个子区，SRD 的某一位置 1 就关掉对应子区。

AP 编码（特权 / 非特权）：

| AP | 特权 | 非特权 |
| --- | --- | --- |
| 0b000 | 不可访问 | 不可访问 |
| 0b001 | 读写 | 不可访问 |
| 0b010 | 读写 | 只读 |
| 0b011 | 读写 | 读写 |
| 0b100 | 不可预测 | 不可预测 |
| 0b101 | 只读 | 不可访问 |
| 0b110 | 只读 | 只读 |
| 0b111 | 只读 | 只读 |

TEX、C、B、S 一起决定 Normal / Device / Strongly-ordered，以及是否可缓存、是否共享。原手册表 39、表 40 是完整编码。常用组合：

| TEX | C | B | S | 结果 |
| --- | --- | --- | --- | --- |
| 000 | 0 | 0 | x | Strongly-ordered，共享 |
| 000 | 0 | 1 | x | Device，共享 |
| 000 | 1 | 0 | 0/1 | Normal，写通，不共享/共享 |
| 000 | 1 | 1 | 0/1 | Normal，写回，不共享/共享 |
| 001 | 0 | 0 | 0 | Normal，不可缓存 |
| 010 | 0 | 0 | x | Device，非共享 |

XN=1 的区域不能取指。

STM32 上 Flash、SRAM 用 Normal，外设用 Device 且 XN。不要把外设区配成可缓存的 Normal，否则写外设寄存器可能被缓冲或合并。

#### 4.1.2 寄存器

MPU、NVIC、ACTLR、SCB、SysTick 和 FPU 的每个寄存器在 [第 5 章](#5-寄存器逐位说明)，含地址、复位值和每一位。

打开 MPU 之前，要么先使能一个区域，要么同时把 `MPU_CTRL.PRIVDEFENA` 置 1。只把 ENABLE 置 1 时，没有落到已使能区域上的访问都会故障。

### 4.2 NVIC

外部中断的使能、挂起和优先级在 NVIC。系统异常的优先级在 SCB 的 SHPR。各位见 [5.3](#53-nvic) 和 [SHPR1](#shpr1)。

CMSIS 不要直接改寄存器位，用这些函数（`core_cm4.h`）：

| 函数 | 作用 |
| --- | --- |
| `NVIC_EnableIRQ` / `NVIC_DisableIRQ` | 使能 / 禁止 |
| `NVIC_SetPendingIRQ` / `NVIC_ClearPendingIRQ` / `NVIC_GetPendingIRQ` | 挂起 |
| `NVIC_GetActive` | 是否正在处理 |
| `NVIC_SetPriority` / `NVIC_GetPriority` | 优先级。函数内部按实现的位数左移，调用者传入 0–15 |
| `NVIC_SystemReset` | 写 `AIRCR.SYSRESETREQ` |

电平中断必须在 ISR 里清掉外设标志，否则返回后立刻再次进入。脉冲中断由挂起位锁存。STM32 外设中断一般是电平式。禁止中断不会清除已挂起的状态。

### 4.3 SCB

故障发生后先看 HFSR。`FORCED` 为 1 再看 CFSR。读 MMFAR 或 BFAR 时，先把地址读出来保存，再看对应的 VALID 位。每个状态位的含义见 [5.4](#54-scb-与-actlr)。

### 4.4 SysTick

24 位递减计数器。初始化顺序是写 LOAD、写 VAL 清当前值、再写 CTRL。`LOAD = 时钟 / 目标频率 - 1`。本工程节拍 1000 Hz，时钟用 `SystemCoreClock`。四个寄存器的位见 [5.5](#55-systick)。

### 4.5 FPU

复位后 FPU 关闭。特权下把 CPACR 的 bit[23:20] 写成 `0b1111`，然后 DSB、ISB。STM32F4 上 IXC 不产生中断，只能轮询 FPSCR。CPACR、FPCCR、FPCAR、FPDSCR、FPSCR 的位见 [5.6](#56-fpu)。


## 5 寄存器逐位说明

本章按原手册把可编程的寄存器逐个列出。表中没出现的位是保留位：读出为 0，写入必须写 0。

优先级字节只实现 bit[7:4]，对应数值 0–15。bit[3:0] 读出为 0，写入被忽略。数值越小，优先级越高。

原手册不描述调试部件，因此 ITM、DWT、TPI、DFSR 不在这里。

### 5.1 内核寄存器

这些寄存器没有存储器地址，用 MRS/MSR 或专用指令访问。

#### R0–R12

32 位通用寄存器。复位值未知。线程模式和处理模式、特权和非特权都可以读写。函数调用时 R0–R3 传参，R0 放返回值，R4–R11 由被调用方保存，R12 是临时寄存器。

#### MSP

R13 的主栈副本。满递减。复位时从向量表第一项（地址 `0x00000000`）装入。只有特权软件能写。处理模式始终使用 MSP。

#### PSP

R13 的进程栈副本。复位值未知。特权和非特权都可以访问。线程模式在 `CONTROL.SPSEL = 1` 时使用它。

#### LR（R14）

保存子程序返回地址。异常进入时硬件改写为 EXC_RETURN。复位值 `0xFFFFFFFF`。

#### PC（R15）

当前指令地址。复位时从 `0x00000004` 装入，该字的 bit0 同时写入 `EPSR.T`，必须为 1。读 PC 得到的是当前指令地址加 4 之后、再按字对齐的值。

#### APSR

条件标志。复位值未知。特权和非特权都可读写。用 `MSR APSR_nzcvq` 写 N、Z、C、V、Q。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31 | N | 读写 | 1：结果为负 |
| 30 | Z | 读写 | 1：结果为 0 |
| 29 | C | 读写 | 1：加法有进位，或减法没有借位 |
| 28 | V | 读写 | 1：有符号溢出 |
| 27 | Q | 读写 | 1：饱和指令把结果饱和过。软件写 0 才能清掉 |
| 26:20 | — | — | 保留 |
| 19:16 | GE[3:0] | 读写 | SIMD 比较的大于或等于标志，每个半字或每两个字节一位 |
| 15:0 | — | — | 保留 |

#### IPSR

只读，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:9 | — | — | 保留 |
| 8:0 | ISR_NUMBER | 只读 | 当前异常号。线程模式为 0。写入被忽略 |

#### EPSR

复位值 `0x01000000`（T=1）。MRS 读出的 EPSR 位为 0，MSR 写入被忽略。T 位由异常返回和复位装入，不能用 MSR 修改。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:27 | — | — | 保留 |
| 26:25 | ICI/IT | 硬件 | IT 块或可继续的 LDM/STM 状态的高段 |
| 24 | T | 硬件 | 1：Thumb 状态。必须保持 1。清 0 后执行指令产生 UsageFault，未使能时升级为 HardFault |
| 23:16 | — | — | 保留 |
| 15:10 | ICI/IT | 硬件 | IT 块或 LDM/STM 继续状态的低段 |
| 9:0 | — | — | 保留 |

组合名：`PSR` 含三段；`IEPSR` 只读，含 EPSR 和 IPSR；`IAPSR` 含 APSR 和 IPSR；`EAPSR` 含 APSR 和 EPSR。

#### PRIMASK

复位值 0。特权，用 MRS/MSR 或 `CPSID i` / `CPSIE i`。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:1 | — | — | 保留 |
| 0 | PRIMASK | 读写 | 0：不额外屏蔽。1：不响应所有可配置优先级的异常。NMI 和 HardFault 不受影响 |

#### FAULTMASK

复位值 0。特权，用 MRS/MSR 或 `CPSID f` / `CPSIE f`。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:1 | — | — | 保留 |
| 0 | FAULTMASK | 读写 | 0：不额外屏蔽。1：除 NMI 以外全部不响应，效果相当于把当前优先级抬到 -1。异常返回时硬件清 0 |

FAULTMASK 为 1 时，可配置故障若发生会升级成 HardFault。

#### BASEPRI

复位值 0。特权。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:8 | — | — | 保留 |
| 7:4 | BASEPRI | 读写 | 0：不屏蔽。非 0：不处理优先级数值大于等于本字段的异常。本内核只实现这 4 位，写入时放在 bit[7:4] |
| 3:0 | — | — | 读出为 0，写入忽略 |

`BASEPRI_MAX` 是 MSR 的另一种写法：只有新值非 0，且优先级高于当前 BASEPRI（数值更小）时才更新。

#### CONTROL

复位值 0。特权可写。非特权可以读，不能改特权级。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:3 | — | — | 保留 |
| 2 | FPCA | 硬件为主 | 1：当前上下文使用过浮点，异常进入时分配浮点栈帧。执行浮点指令且 `FPCCR.ASPEN = 1` 时硬件置 1。`ACTLR.DISFPCA` 应保持 0，否则这个自动更新被关掉 |
| 1 | SPSEL | 读写 | 0：线程模式用 MSP。1：线程模式用 PSP。处理模式忽略此位 |
| 0 | nPRIV | 读写 | 0：线程模式为特权。1：线程模式为非特权。只有特权软件能写 |

#### S0–S31

32 个单精度浮点寄存器，也可以成对当作 16 个双字用于加载、存储和传送。无存储器地址。FPU 未通过 CPACR 打开时，访问它们产生 UsageFault（NOCP）。复位值未知。

### 5.2 MPU

基址 `0xE000ED90`。是否带 MPU 以具体型号为准；STM32F429 有 8 个区域。除 RASR 可以按半字访问外，用对齐的字访问。

区域重叠时，编号大的生效。改完配置后执行 DSB 再执行 ISB，或通过异常返回，后面的指令才使用新属性。

#### MPU_TYPER

地址 `0xE000ED90`，只读，特权。复位值 `0x00000800`。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:24 | — | — | 保留 |
| 23:16 | IREGION | 只读 | 独立的指令区域数。统一映射，固定为 0 |
| 15:8 | DREGION | 只读 | 数据区域数。本内核为 8 |
| 7:1 | — | — | 保留 |
| 0 | SEPARATE | 只读 | 0：指令和数据共用一套区域 |

#### MPU_CTRL

地址 `0xE000ED94`，读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:3 | — | — | 保留，硬件强制为 0 |
| 2 | PRIVDEFENA | 读写 | 1：打开背景区域。特权软件访问没有落到任何已使能区域上的地址时，使用默认存储器映射。非特权没有背景区域 |
| 1 | HFNMIENA | 读写 | 0：执行 NMI 或 HardFault，以及 FAULTMASK 为 1 时，MPU 不生效。1：这两种优先级下 MPU 仍然生效。此位只有在 ENABLE 为 1 时有意义 |

#### MPU_RNR

地址 `0xE000ED98`，读写，特权。复位值 0。选择后面 RBAR 和 RASR 作用的区域。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:8 | — | — | 保留，硬件强制为 0 |
| 7:0 | REGION | 读写 | 区域号。本内核使用 0–7 |

#### MPU_RBAR

| --- | --- | --- | --- |
| 31:N | ADDR | 读写 | 区域基址。N = log2(区域字节数)，由 RASR.SIZE 决定。基址必须按区域大小对齐。区域为 4 GB 时没有 ADDR 字段，基址视为 `0x00000000` |
| N-1:5 | — | — | 保留，硬件强制为 0 |

| 31:29 | — | — | 保留，硬件强制为 0 |

| 27 | — | — | 保留，硬件强制为 0 |
| 26:24 | AP | 读写 | 访问权限，见下表 |
| 23:22 | — | — | 保留，硬件强制为 0 |

| 18 | S | 读写 | 1：可共享 |
| 17 | C | 读写 | 可缓存属性 |
| 16 | B | 读写 | 缓冲属性 |
| 15:8 | SRD | 读写 | 8 个子区的禁止位。bit i 为 1 时关掉第 i 个子区。区域小于 256 字节时必须写 0 |

| 5:1 | SIZE | 读写 | 区域大小 = 2^(SIZE+1) 字节。最小允许值是 4，对应 32 字节 |
| 0 | ENABLE | 读写 | 1：本区域参与保护 |

| AP | 特权 | 非特权 |
| --- | --- | --- |
| 000 | 不可访问 | 不可访问 |

| 010 | 读写 | 只读 |

| 101 | 只读 | 不可访问 |
| 110 | 只读 | 只读 |
| 111 | 只读 | 只读 |

TEX、C、B 的常用编码：

| TEX | C | B | 类型 | 共享 | 缓存策略 |
| --- | --- | --- | --- | --- | --- |
| 000 | 0 | 0 | Strongly-ordered | 始终共享 | — |
| 000 | 0 | 1 | Device | 始终共享 | — |
| 000 | 1 | 0 | Normal | 由 S 决定 | 内外都写通，不写分配 |
| 000 | 1 | 1 | Normal | 由 S 决定 | 内外都写回，不写分配 |
| 001 | 0 | 0 | Normal | 由 S 决定 | 内外都不可缓存 |
| 001 | 1 | 1 | Normal | 由 S 决定 | 内外都写回，读写都分配 |
| 010 | 0 | 0 | Device | 不共享 | — |

TEX[2] 为 1 时，TEX[1:0] 是外部策略，C 和 B 是内部策略。策略编码：00 不可缓存，01 写回且读写分配，10 写通且不写分配，11 写回且不写分配。001 的其余组合以及 010 除了 00 以外是保留或实现定义，不要使用。

| 15 | 64 KB | 16 |

#### MPU_RBAR_A1、MPU_RBAR_A2、MPU_RBAR_A3

地址分别是 `0xE000EDA4`、`0xE000EDAC`、`0xE000EDB4`。位定义与 MPU_RBAR 相同，是它的别名。用来在不单独写 RNR 的情况下连续配置后面的区域。

#### MPU_RASR_A1、MPU_RASR_A2、MPU_RASR_A3

地址分别是 `0xE000EDA8`、`0xE000EDB0`、`0xE000EDB8`。位定义与 MPU_RASR 相同，是它的别名。

### 5.3 NVIC

外部中断用这一组寄存器。系统异常的优先级在 SHPR，不在 IPR。除 IPR 可以按字节访问外，使用对齐的字。中断个数以器件为准，架构最多 240 个（IRQ0–IRQ239）。`NVIC_ISER7` 到 `NVIC_IABR7` 的 bit[31:16] 保留。

bit n 对应的 IRQ 号是 `32 × x + n`。

#### NVIC_ISERx

x 为 0–7。地址 `0xE000E100 + 4x`。读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:0 | SETENA | 读写 | 写 1：使能对应中断。写 0：无作用。读 0：未使能。读 1：已使能。已挂起的中断一旦被使能，NVIC 按优先级决定是否进入处理。未使能时，中断请求只把状态变成挂起，不会激活 |

#### NVIC_ICERx

x 为 0–7。地址 `0xE000E180 + 4x`。读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:0 | CLRENA | 读写 | 写 1：禁止对应中断。写 0：无作用。读值与 ISER 相同，1 表示当前仍使能。禁止不会清除挂起位 |

#### NVIC_ISPRx

x 为 0–7。地址 `0xE000E200 + 4x`。读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:0 | SETPEND | 读写 | 写 1：把对应中断置为挂起。写 0：无作用。读 1：该中断处于挂起。中断未使能时也可以挂起，使能后才会被处理 |

#### NVIC_ICPRx

x 为 0–7。地址 `0xE000E280 + 4x`。读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:0 | CLRPEND | 读写 | 写 1：清除挂起。写 0：无作用。读 1：当前仍挂起。正在处理的中断不会因为清挂起而退出 |

#### NVIC_IABRx

x 为 0–7。地址 `0xE000E300 + 4x`。只读，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:0 | ACTIVE | 只读 | 1：该中断正在被处理，包括被更高优先级异常抢占、尚未返回的情况 |

#### NVIC_IPRx

字地址 `0xE000E400 + 4x`，x 为 0–59，共 240 个字节优先级，每个中断一个字节。字节地址 `0xE000E400 + N` 就是 IRQ N 的优先级。读写，特权。复位值 0。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:24 | IP[4x+3] | 读写 | 一个优先级字节 |
| 23:16 | IP[4x+2] | 读写 | 一个优先级字节 |
| 15:8 | IP[4x+1] | 读写 | 一个优先级字节 |
| 7:0 | IP[4x+0] | 读写 | 一个优先级字节 |

每个字节只用 bit[7:4]。写 `0x50` 和写 `0x5F` 对硬件都是优先级 5。中断已经挂起或正在处理时修改优先级，写完要加 DSB。

电平中断必须在 ISR 里清掉外设标志，否则返回后立刻再次进入。脉冲中断由挂起位锁存，太窄而没被采样到的脉冲会丢失。STM32 外设中断一般是电平式。

#### NVIC_STIR

地址 `0xE000EF00`。只写，特权。`CCR.USERSETMPEND` 为 1 时非特权也可以写。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:9 | — | — | 保留 |
| 8:0 | INTID | 只写 | 写入 IRQ 号，使该中断挂起。作用与对 ISPR 写 1 相同 |

### 5.4 SCB 与 ACTLR

SCB 基址 `0xE000ED00`。除 CFSR 和 SHPR1–SHPR3 可以按字节或半字访问外，必须用对齐的字。不支持非对齐访问。

#### ACTLR

地址 `0xE000E008`。读写，特权。复位值 0。默认已经是性能取向，一般不要改。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:10 | — | — | 保留 |
| 9 | DISOOFP | 读写 | 1：禁止浮点指令相对于整数指令乱序完成 |
| 8 | DISFPCA | 读写 | 1：禁止硬件自动更新 `CONTROL.FPCA`。应写 0 或保持原值 |
| 7:3 | — | — | 保留 |
| 2 | DISFOLD | 读写 | 0：允许 IT 折叠，IT 和下一条指令可以重叠执行。1：禁止折叠。循环里要避免由此带来的节拍抖动时再置 1 |
| 1 | DISDEFWBUF | 读写 | 0：默认存储器映射的写可以使用写缓冲。1：关掉写缓冲，存储完成后才执行下一条指令，BusFault 都变成精确故障，性能下降 |
| 0 | DISMCYCINT | 读写 | 0：多周期的加载/存储和乘除可以被异常打断。1：LDM/STM 等必须做完才能压栈进入异常，中断延迟变大 |

#### CPUID

地址 `0xE000ED00`。只读，特权。复位值 `0x410FC241`。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31:24 | Implementer | 只读 | `0x41`：Arm |
| 23:20 | Variant | 只读 | 版本号里的 r。本值为 0 |
| 19:16 | Constant | 只读 | 固定 `0xF` |
| 15:4 | PartNo | 只读 | `0xC24`：Cortex-M4 |
| 3:0 | Revision | 只读 | 版本号里的 p。本值为 1 |

#### ICSR

地址 `0xE000ED04`。读写，特权。复位值 0。同一次写入里不要同时把某一异常的 SET 和 CLR 都写成 1，结果不可预测。

| 位 | 名称 | 访问 | 说明 |
| --- | --- | --- | --- |
| 31 | NMIPENDSET | 读写 | 写 1：挂起 NMI。读 1：NMI 已挂起 |
| 30:29 | — | — | 保留 |

### 5.5 SysTick

基址 `0xE000E010`。24 位递减计数器。减到 0 的下一个时钟沿从 LOAD 重新装入。调试器停住内核时不计数。处理器时钟停掉时也不计数。必须用对齐的字访问。

初始化顺序：先写 LOAD，再写 VAL 清当前计数，最后写 CTRL。

节拍：`LOAD = 时钟 / 目标频率 - 1`。时钟在 `CLKSOURCE` 为 1 时是 AHB，为 0 时是 AHB/8。24 位计数上限是 `0xFFFFFF`。

### 5.6 FPU

实现 FPv4-SP：单精度加、减、乘、除、乘加和平方根，以及浮点与整数、浮点与定点数的转换。复位后 FPU 关闭。

使能必须在特权下进行：把 CPACR 的 bit[23:20] 写成 `0b1111`，然后 DSB、ISB，才能执行浮点指令。CP10 和 CP11 必须写成相同的访问级别。

STM32F4 没有按标志位单独屏蔽 FPU 异常的 SYSCFG 位，开关在 NVIC。IXC 没有接到中断控制器，只能轮询 FPSCR，不能靠中断。

清异常标志取决于压栈方式：

- `ASPEN = 0` 且 `LSPEN = 0`：直接改 FPSCR 里的异常位
- `LSPEN = 1`：先读一次 FPSCR，迫使懒压栈完成，再改栈上 `FPCAR + 0x40` 处保存的 FPSCR，然后 DMB
- `ASPEN = 1` 且 `LSPEN = 0`：FPSCR 已经在栈帧里。返回码 `0xFFFFFFE9` 时帧在 MSP 侧，`0xFFFFFFED` 时在 PSP 侧，FPSCR 位于栈帧基址加 `0x60`

## 和本工程的对应关系

| 手册里的机制 | 本工程 |
| --- | --- |
| 4 位优先级，0–15 | `configPRIO_BITS` 为 4，最低优先级 15 |
| 高于某阈值的中断不能调用操作系统 API | `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 为 5 |
| SysTick 做系统节拍 | `configTICK_RATE_HZ` 为 1000，`xPortSysTickHandler` 即 `SysTick_Handler` |
| PendSV 做上下文切换 | `xPortPendSVHandler` 即 `PendSV_Handler` |
| SVC 进入特权服务 | `vPortSVCHandler` 即 `SVC_Handler` |
| MSP 给定时器和中断用，PSP 给任务用 | FreeRTOS 移植层在启动调度器时切换 |
| FPU 懒压栈 | 任务里使用 `float` 时依赖内核已使能 FPU，栈深度要包含扩展帧 |
